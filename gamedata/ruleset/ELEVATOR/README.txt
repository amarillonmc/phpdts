ELEVATOR：帧间电梯
=================

怎样开始
--------
在首页的异色模式列表选择 ELEVATOR，按现有开房流程开始。普通账户开房花费1切糕，管理员沿用免费设置。
开局前10分钟可以加入，最多8人，每账户每局只领取一次起装。提供六种起始武器路线，均为400生命、400体力、300现金，附武器、防具、恢复品和猫粮。

电梯面板负责楼层、候乘、交互、配方、遗物、行商和交易；搜索、战斗、装备、拾取、搜尸仍走原生游戏操作。
面板上方可跳到装备/战斗、操作/拾取和行动日志。default 与 nouveau 均可使用。页面可见时每4秒刷新状态，操作与刷新共用原有 postCmd。

有限段可到 +1～+7、−1～−8。每层由2～5个内容点和电梯口组成；在两个不同内容点有效探索后获得一件六选一遗物。
电梯内按钮先到先服务，并优先于层外呼叫；已经承诺的目的地不被后来请求改写。到站、开门8秒、关门5秒完成后再处理下一程，移动每层3秒。
在电梯口登记且没有走开的乘客会自动上车；没有登记的人不会被自动搬走。下车要等车门完全打开。

个人暴露预算由150秒递减至最低100秒，耗尽后每秒侵蚀8生命。出生和复活有60秒入口保护，候梯暂停，离开入口或电梯离站后恢复消耗。
页面断线后不补扣整段离线时间；在线状态采用12秒报到窗口，关闭页面后最多还有这段已确认的在线时间。重新连接不会刷新预算。
全程禁止PVP，所有复活来源共用一次额度；第一次死亡以30%生命回电梯口，第二次个人结算，不终止其他人的游戏。

±3、±5、±7可以个人脱出。−8为没有战斗、没有侵蚀的灰色会客厅，听完大种火的三个问题即可离开，答错不卡流程。
终点可发起120秒无尽提案，同意者留下，其余乘客胜利离场。无尽上行增加谜题和镜像出现率，下行继续增加战斗难度。无尽不再提供普通脱出。
有限段最长60分钟，无尽整局最长90分钟；全员离场或到时后以 end8 封存。主动提前退出按参与奖励结算。

内容与收益
----------
64个场景模板、八个主题池、129种原案物品、23种交互对象，均已有实际投放/操作。
每层2～4只随机杂兵，另有25%概率出现1只精英；上行防御倾向、下行攻击倾向。复制水龙头限6轮，镜像保留战斗属性但不复制装备掉落，半成品在半血时退场。
七类入侵含20秒预告、交互/战斗、超时失败和重新开门。战斗入侵后的两次停靠与60秒冷却须同时满足。

每局10张随机配方（独立生成器默认30），70%学习型、30%消耗型。学习保存到本局 clbpara，学习型蓝图保留；换局配方与学习记录不继承。
蓝图号放在 R 的 itmsk，独立合成入口，不修改公共 mixinfo。主素材按类别，其他素材来自本模式投放和行商；保留含[+5]强化武器的无限耐久配方分支。
近战武器、枪械、防具按整件消耗；可叠加武器/垃圾/恢复品按份数消耗。失败、旧蓝图或旧物品凭据不扣材料。
遗物六选一来自本层实际主题池、补给和常磐技能书，不放回抽取；首次打开的选项保存在物品para，转手不重抽。有限段10%混入蓝图，深层每三层提高权重。
行商常备补给和素材，180秒刷新随机货架；购物、小费、情报、出售均可用。唯一剧情物品不由商店复制。攻击后永久敌对，库存最多六件进入原生搜尸槽。
车厢提供六格个人保管箱，以及报价/接受式交易；0现金为赠送。报价120秒有效，超时、离厢或入侵自动退还。
灰层谜面和选项为英文单表替换；得到手册后显示英文。阁楼历史场景、珠子与弹幕为本次新写的虚构内容，不使用真实玩家私密材料。

切糕：退出2；有限死亡2+max(有效深度−1,0)；±3脱出5、±5脱出8、±7和−8脱出12；单人±7另加3；提案离场10；无尽死亡8+max(有效深度−8,0)，上限30。
620～629为电梯成就，奖励依次10/20/20/30/50/77/30/100/30/50。9201～9205为纯荣誉称号，不给入场属性。
有效深度以完成本层两处探索为准。同深度按首次达到的整局用时排序；上下行无尽分榜，在结算页和车厢荣誉墙展示。

部署与时钟
----------
使用本项目现有安装/数据库配置，不执行 Composer，也不清空 gamedata/cache。
模式首次加载会在现有 process.lock 内把当前房间 players/mapitem/maptrap 的 pls 从 tinyint 扩为 int unsigned，保留数据。
会建立当前房间前缀的 elevator_floor（楼层内容）和公共前缀的 elevator_results（个人结果、奖励发放标记及榜单）。数据库账户需具备相应建表/改表权限。
新房结构沿用 gamedata/sql；install/bra.sql 本身没有玩家/地图物品/陷阱三张实时表定义，无需把模式运行数据塞进安装快照。

运行中的网页请求会推进时钟。需要无人打开页面时也按时推进，可从仓库根目录启动：
  php -d short_open_tag=1 bot/elevator_tick.php 房间号 --watch
例如主房是0，小房使用其实际编号。每秒推进一次；准备阶段可等到开局，封存后退出。每局由部署方启动/管理该进程。
也可以定时执行一次：
  php -d short_open_tag=1 bot/elevator_tick.php 房间号
CLI只接受实际存在的ELEVATOR房间；采用部署时差后的 now，和HTTP共用 process.lock。没有运行独立时钟时，下次请求补偿推进电梯/投票/截止时刻。

状态归属
--------
gamevars.elevator：本局电梯、请求队列、15层有限蓝图、唯一物品发放标记、少量广播；rr_recipes为固定容量配方表。
clbpara.elevator：个人位置、预算、复活、探索、保管箱、交易和结算标记。无尽细节仅保留最近八层，探索奖励进度用上下行最大值避免回收后重领。
itmpara：原案物品标记、局号、遗物标识和六选一结果；跟随物品拾取、掉落、交易、保管。
elevator_floor：已实例化的楼层。无人、无请求且距离当前层超过两层的旧无尽层可回收。
elevator_results：以局号+账户为唯一键；付款SQL同时更新账户和paid，重复请求不重复发钱。
不新增通用服务、版本协议或全局合成注册层。公共新增接点只覆盖移动/遭遇/战斗结算与临时属性，未启用规则集时保留原分支。

运行地点：车厢9000，入口10000+(abs(floor)*2+(floor<0?1:0))*16，内容点再加1～5，隐藏地图组250/251。
未采用交接示例的车厢10050，因为它会和本版−1层第二个内容点（10048+2）重合。逻辑楼层、模板ID、运行地点各有用途。

来源与冲突处理
--------------
优先采用用户提供的 elevator_handoff.md 完整模式规格，以及 randnpc_randrecipe_elevator_port_handoff.md 的移植技术细节；“只做卷一/只迁两个模块”是旧交接范围，不限制本次完整实装请求。
两份交接冲突处：完整模式的1.15生命曲线、每层2～4杂兵、每局8～12配方覆盖较早的模块建议；本版取10配方。学习按技术段“蓝图保留”、clbpara本局学习执行。
原案论坛 https://91bb.icu/index.php?topic=48.0 在本次环境访问失败。物品名、效果、数量和场景依据仓库 doc/20260915-024212-elevator-ruleset-design-review.md 附录C及创作资料库复核；未声称完成论坛原始CSV逐列还原。
缺失的投放份数与地点配置按每种一次、贴合主题的场景归属补齐，剧情关键物品17种全局唯一；这些是可测试的首版投放，不是原帖已经确认的精确经济平衡。
参考 dts 源 instance10_rogue/randnpc、randrecipe 的生成结构；不带入电波实例任务/结局、复合属性、连接合成、ygo/extra判定系统。
三道谜语按交接草稿译写英文；其余需要的场景、对话、提示、结束文案和图像已随本版提供，可继续润色。
