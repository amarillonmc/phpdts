PHPDTS 模板缓存目录自动重建
日期：2026-10-27
基于提交：cbf6a29799baef45d4f25f536aa897f2bc46db23

实际运行代码改动：include/template.func.php

问题
FTP 清理误上传的目录时，正常的 gamedata/templates 模板缓存目录也不可用了。
旧编译器在 fopen 写缓存失败后调用 gexit；gexit 又尝试编译 error 模板，
同一个缓存目录故障便反复进入错误页编译，造成请求不返回及内存增长。

修改
1. 在 parse_template 开始时检查 gamedata/templates，不存在则请求以 0755
   创建这一层目录。随后 clearstatcache 并重新检查，接受并发请求已经创建
   成功的情况。现有目录权限不变；最终创建权限仍受进程 umask 影响。
2. 编译器的源模板打开失败、语言包加载失败、缓存文件打开失败，改为调用
   独立 dts_template_error。它写入带 [PHPDTS template] 前缀的 error_log，
   丢弃尚未发送的页面缓冲，能修改响应头时返回 HTTP 500 和固定纯文本提示，
   然后立即退出，不再使用 gexit 渲染错误模板。
3. 源模板用 stream_get_contents 读取，仅把 false 判定为读取失败，
   允许现有的零字节 css.htm 正常编译。

部署
将包中的 include/template.func.php 覆盖到真实网站根目录的同名路径。
本次 FTP 日志对应的远端目标是：
  /public_html/dts1/include/template.func.php
同步修改自己的本地代码仓库，以免下次上传旧文件覆盖本修复。
doc 中的本说明用于维护记录，不参与请求处理。

行为与边界
- 当前站点 tplrefresh=1；缺少编译缓存会进入 parse_template，自动建目录，
  然后按原流程重新生成需要的 .tpl.php 文件。
- 若父目录 gamedata 不可写、模板缓存路径被普通文件占用，或其他权限问题
  阻止创建/打开文件，则记录错误并直接结束请求；代码不能绕过文件系统权限。
- 没有递归创建整个 gamedata，没有删除数据、修改数据库或修改玩法。
- 原模板替换规则和缓存 flock/fwrite 流程保持原样。
- 保留 tplrefresh=0 的原有语义：该配置不会自动进入模板编译器。
- 本补丁处理编译器内的失败路径；global.func.php 的 template() 在进入
  编译器之前处理缺失源模板的逻辑不在本次修改范围内。

验证
使用官方源码构建的 PHP 7.4.33 CLI，开启 short_open_tag，在隔离临时目录运行：
- 修改文件的 PHP 语法检查通过。
- 使用真实 template() 入口，无缓存目录时成功建目录、编译并执行首页和页尾。
- 已有目录的 0700 权限及其中无关文件保持不变。
- 正常模板的编译 PHP 内容与渲染输出和旧编译器一致。
- 零字节 CSS 模板成功编译，无 PHP Warning。
- 用普通文件占据缓存目录路径：立即退出、仅一条独立错误日志、状态 500，
  原占位文件不被覆盖，没有生成或执行错误页模板。
- 用目录占据缓存文件路径并触发刷新：立即退出、状态 500，清除部分页面缓冲。
- 编译器源模板打开失败和语言包失败：直接退出，没有递归生成错误页。
- diff 空白检查无报错。
这些是离线行为验证，未在生产站点部署此补丁。
