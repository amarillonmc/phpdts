# 未完成和异常实现观察

这个文件记录本次梳理文档时看到的“似乎没做完”“实现比较奇怪”“容易误用”或“目前不像通用能力”的地方。这里不直接判定历史设计对错，只给后续讨论和修复提供线索。

## 背包重量系统像是预留但未启用

位置：

```text
include/game/itembag.func.php
```

现象：

- 注释里写了 `$weight`、`$weightlimit`、`$itmwtinfo`。
- `item_weight()`、`getitem_weight()` 存在。
- `item_get()` 中实际超重判断整段被注释。

影响：

当前背包主要按数量上限工作，不按重量限制。文档或设计里不应把重量写成已实装机制。

后续建议：

如果要启用重量，需要补全 `$itmwtinfo` 默认值、未登记道具的兜底、装备重量计算，以及 UI 显示。

## 背包替换分支疑似有 SQL 和参数问题

位置：

```text
include/game/itembag.func.php
```

现象：

- `replace_itembag()` 中替换普通物品栏背包的分支，SQL 使用 `{${'itm'.$i}}` 这类未加引号的插值。
- 相关 `INSERT` 没有写 `itmpara` 字段。
- 替换身体防具背包时设置 `$arbpara = $itmpara0`，但函数 global 里没有 `$arbpara`，装备参数字段命名也需要确认。

影响：

如果这个分支被实际触发，可能插入失败、掉落数据不完整或参数丢失。

后续建议：

统一用和 `drop_itembag()` 类似的完整字段插入，并检查装备参数字段名。

## 视界切换成本公式有未来配置风险

位置：

```text
include/game/search.func.php
```

现象：

移动/搜索成本在某些分支中用 `round($costsp * $costspr)` 判断，但实际扣除仍可能扣 `$costsp`。当前配置下差异不明显，但如果未来调整比例，判断和扣除可能不一致。

影响：

未来改视界消耗倍率时可能出现“检查能行动，但扣除不是同一个值”的问题。

后续建议：

把实际要扣的 HP/SP 数值先算成变量，再统一用于判断和扣除。

## 对话模板同时引用 `dialogue_ending` 和 `dialogue_end`

位置：

```text
gamedata/cache/dialogue_1.php
templates/default/dialogue.htm
```

现象：

配置文件定义的是 `$dialogue_ending`，模板还兼容/引用 `$dialogue_end`。

影响：

容易让改造者误以为两者都应配置。当前应以 `$dialogue_ending` 为准，`$dialogue_end` 更像旧变量残留。

后续建议：

统一变量名，或在配置文件注释里明确 `$dialogue_end` 是兼容旧名。

## 对话选择主要只记录，不执行通用分支效果

位置：

```text
command.php
gamedata/cache/dialogue_1.php
```

现象：

选择分支会记录选择内容并输出日志，然后清除对话状态。没有通用的“选择后给道具/改地点/触发任务/进结局”配置执行器。

影响：

剧情配置可以做选项展示，但不能只靠配置做复杂分支。

后续建议：

如果需要剧情编辑友好，可以设计 `dialogue_effects` 配置，并在选择处理后统一执行。

## 成就 38 的阶段分支疑似写错成就编号

位置：

```text
include/game/achievement.func.php
```

现象：

搜索结果显示，处理成就 38 时，`fetch_achievement_rev(38)` 的一个阶段分支调用了：

```php
done_achievement_rev(37, 2, $nn);
```

而同一段上下文其它分支在处理 38。

影响：

可能导致成就 38 的阶段奖励/完成状态写到成就 37。

后续建议：

对照 `achievement_1.php` 中 37/38 的定义和实际奖励，确认是否为笔误。

## RuleSet 配置看起来通用，函数覆盖加载却是特例

位置：

```text
gamedata/ruleset/ruleset_config.php
include/ruleset_override.func.php
```

现象：

配置里有 `override_modules`，但 `load_ruleset_override_functions()` 实际只对 `ACDTS_298SP4_AR` 加载固定路径：

```php
gamedata/ruleset/ACDTS_298SP4_AR/include/ruleset_functions.php
```

影响：

新增 RuleSet 想通过配置自动加载专用 PHP 函数，目前不像通用能力。

后续建议：

改成根据当前 RuleSet ID 和配置动态加载白名单文件，并处理不存在文件的错误提示。

## RuleSet 创建权限函数会写调试文件

位置：

```text
gamedata/ruleset/ruleset_config.php
```

现象：

`can_create_ruleset_room()` 多个分支都会向 `doc/etc/can_create_debug_时间.txt` 写调试文件。

影响：

生产环境中频繁检查权限可能产生大量调试文件，也可能因为目录权限导致警告。

后续建议：

加调试开关，默认关闭文件写入。

## RuleSet 配置存在主配置和 fallback 重复，且价格不同

位置：

```text
gamedata/ruleset/ruleset_config.php
```

现象：

文件前部定义了一套 `$ruleset_config`，后部 `get_ruleset_config()` 内还有 fallback `$local_ruleset_config`。同一 RuleSet 的 `credits_cost` 可能不同，例如前部是较小值，fallback 是 100/150/200/300 这种旧值。

影响：

如果加载路径走到 fallback，用户看到的价格和实际扣费规则可能不一致。

后续建议：

保留单一配置源，fallback 只用于极端缺省，并明确不会覆盖主配置。

## RuleSet story 有两套并行结构

位置：

```text
gamedata/ruleset/story_config.php
game.php
templates/default/ruleset_*_story.htm
```

现象：

同时存在 `$ruleset_stories` 和 `$ruleset_story_pages`。前者像简单弹窗故事，后者像分镜页面故事。不同入口可能读取不同结构。

影响：

改造者可能改了其中一套却看不到效果。

后续建议：

明确哪套是当前推荐接口，另一套标为兼容旧实现。

## 隐藏地图声音/音效生成有 TODO 痕迹

位置：

```text
gamedata/cache/resources_1.php
include/game/search.func.php
```

现象：

隐藏地点配置附近有注释提到隐藏地图目前不生成 sound。

影响：

如果改造目标依赖声音/足音/地点提示，隐藏地图可能不完整。

后续建议：

梳理声音生成逻辑，把隐藏地图纳入同一套地点判定。

## `mapitem_1.php` / `shopitem_1.php` 解析不是完整 CSV

位置：

```text
include/system.func.php
gamedata/cache/mapitem_1.php
gamedata/cache/shopitem_1.php
```

现象：

解析主要靠 `explode(',')` 和少量针对 JSON 的特殊处理，不是完整 CSV parser。

影响：

道具名或参数里有复杂逗号、引号、嵌套 JSON 时容易错位。

后续建议：

要么限制资源格式并写入文档，要么迁移成 PHP 数组或真正 CSV 解析。

## `get_ruleset_plain_resource_file()` 与 `config()` 路径规则不一致

位置：

```text
include/resources.func.php
include/global.func.php
```

现象：

大多数资源通过 `config()` 从 RuleSet 的 `cache/` 目录读取；任务扩展等通过 `get_ruleset_plain_resource_file()` 从 RuleSet 根目录读取。

影响：

很容易把 `questcfg_1.php`、`questitem_1.php`、`addnpc_quest_1.php` 放错目录。

后续建议：

统一路径策略，或在规则集目录提供 README/检查器提示。

## 结局编号解析对多位数不友好

位置：

```text
include/system.func.php
```

现象：

`gameover()` 对字符串模式类似 `end3` 使用 `substr($mode, 3, 1)` 取结局编号。

影响：

`end10` 会被解析成 `1`，除非另有特殊逻辑处理。

后续建议：

改成取 `substr($mode, 3)` 并转整数。

## 旧版文档存在与当前实现不符的表述

位置：

```text
doc/nouveau_250609/
```

现象：

旧文档里有一些现代框架/API/规范式描述，和当前“全局变量 + 函数库 + 自定义模板 + 资源配置”的实际项目形态不完全一致；部分玩法说明也过度概括。

影响：

新改造者按旧文档理解，可能找错入口或误判系统能力。

后续建议：

保留旧文档作历史资料，但在入口标注新版文档为准。
