# 08 - 排错手册

本章按症状排查。新手改 PHPDTS 最常见的问题不是复杂算法，而是编码、语法、缓存、生效时机和资源格式。

## 打开游戏是白屏

先做四件事：

1. 看 PHP 错误日志。
2. 对刚改过的 PHP 文件跑 `php -l`。
3. 确认文件是 UTF-8 无 BOM。
4. 确认 `<?php` 前没有空格、空行或不可见字符。

常见原因：

- 少了分号。
- 数组括号没闭合。
- 字符串引号没闭合。
- PHP 文件保存成 UTF-8 with BOM。
- 直接输出导致 `headers already sent`。
- 修改了 `include/common.inc.php` 或配置文件导致初始化中断。

## 页面显示 `Access Denied`

如果你直接访问 `include/game/*.php` 或 `gamedata/cache/*.php`，看到 `Access Denied` 是正常的。这些文件要求先定义 `IN_GAME`，只能被游戏入口包含。

如果正常进入游戏也出现，说明某个文件被错误地直接请求，或者入口初始化断了。

## 改了地图物品但游戏里没有

检查：

- 是否新开了一局。
- 是否改的是当前 RuleSet 读到的资源。
- `mapitem_1.php` 字段数量是否正确。
- `imap` 是否是合法地点。
- `iarea` 是否对应当前阶段。
- 道具是不是陷阱类型 `TO*`，进了 `maptrap` 而不是 `mapitem`。
- 搜索时可能先遇到 NPC、尸体、陷阱，不一定马上见到物品。

旧局已经生成过地图物品，不会因为你改了资源文件自动重建。

## 改了商店但商品不显示

检查：

- 当前位置是否在 `$shops` 中。
- 商品 `kind` 是否对应商店分类。
- `num > 0`。
- `price > 0`。
- `area` 是否已解锁。
- 是否改了 RuleSet 对应的 `shopitem_1.php`。
- CSV 风格行尾是否缺字段。

## 改了模板但页面没变

模板会编译到：

```text
gamedata/templates/
```

排查：

- 是否改错模板目录。Nouveau 模板缺文件会回退 default。
- `tplrefresh` 是否关闭。
- 编译缓存是否比模板新。
- 浏览器是否缓存了 CSS/JS。
- 模板语法是否写错，导致编译后的 PHP 报错。

临时测试可以删除对应 `gamedata/templates/*.tpl.php` 缓存。

## JSON 参数没生效

常见错误：

```php
'{QuestID:Q1}'
```

这是错的。合法 JSON 要双引号：

```php
'{"QuestID":"Q1"}'
```

排查：

- 键和值是否使用双引号。
- 最后一个字段后是否多了不该有的逗号。
- 外层 PHP 字符串引号是否包对。
- 读取方是否真的调用了 `get_itmpara()` 或 `get_clbpara()`。
- 代码是否把非 JSON 字符串当数组使用。

## CSV 风格资源错位

`mapitem_1.php`、`shopitem_1.php` 不是完整 CSV 解析器。不要依赖复杂引号和转义。

常见问题：

- 道具名里有英文逗号。
- 少了最后的空字段。
- JSON 里有逗号但格式不是简单对象，解析器没处理好。
- 把中文逗号 `，` 和英文逗号 `,` 混用。

解决办法：

- 道具名尽量不用英文逗号。
- 每行字段数对齐。
- 复杂参数优先放 PHP 数组资源，而不是 CSV 风格资源。

## NPC 没出现

检查：

- 是否新开局。
- `npc_1.php` 语法是否通过。
- `mode` 是否是当前初始化逻辑支持的模式。
- `num` 是否大于 0。
- `pls` 是否合法。
- `pls=99` 是否被随机逻辑避开了禁区/深层区。
- `sub` 是否写错导致覆盖了关键字段。
- 当前 RuleSet 是否覆盖了 `npc_1.php`。

动态 NPC 还要检查 `addnpc()` 有没有被调用。

## NPC 出现但搜不到

检查：

- 玩家和 NPC 的 `horizon` 是否一致。
- NPC 是否在禁区或隐藏地点。
- 玩家是否在同一地点。
- 死斗阶段规则是否改变了遭遇限制。
- 搜索流程是否先触发了其他事件。

灵子视界 NPC 需要玩家也进入灵子视界。

## 背包不能用

检查：

- 背包道具 `itmsk` 是否包含 `^`。
- 背包是否在当前逻辑识别的槽位。
- `itme` 和 `itms` 是否大于 0。
- 玩家是否已经有另一个背包。
- 要收入的物品是否带 `V` 或 `v`。
- 背包容量是否已满。

当前重量系统基本是预留，不要按重量方向排查。

## 新技能没有按钮

检查：

- 技能是否真的注册到玩家 `clbpara`。
- `$club_skillslist` 是否包含该技能。
- `$cskills` 里是否有定义。
- `input`、`tags`、`status` 等字段是否照同类主动技能写。
- 是否有对应模板。
- `command.php` 的 `revskpts` 分支是否能处理这个主动技能。
- `revclubskills_extra.func.php` 是否有执行逻辑。

配置能显示技能，不代表主动效果已经实现。

## 成就不触发

检查：

- `achievement_1.php` 是否只加了配置，没有触发逻辑。
- 对应 `check_*_achievement_rev()` 是否覆盖这个行为。
- 完成时传入的是用户名，不是昵称或玩家 ID。
- 阶段值是否写对。
- 用户 `achrev` 是否已有更高阶段。
- RuleSet 是否使用了不同成就配置。

## 任务不出现

检查：

- 游戏是否已经开始。
- 玩家是否已有待确认任务或活跃任务达到上限。
- `assign_obbs`、`offer_threshold`、冷却是否挡住。
- 玩家 `itm0` 是否被占用，任务物品可能无法放入。
- `questcfg_1.php` 是否在当前 RuleSet 正确路径下。

## 任务道具没效果

检查：

- `itmk` 是否是任务处理器识别的类型，例如 `YQ`。
- `itmpara` JSON 是否合法。
- `QuestID` 是否存在。
- `QuestAction` 是否在 `item.quest.php` 有分支。
- 任务当前状态是否允许该动作。

## 剧情选项没有改变结果

这通常不是 bug。当前对话选择主要记录在 `clbpara`，并输出日志。要让选项改变道具、地点、任务、结局，需要另写逻辑读取选择结果。

## 新结局显示不对

检查：

- `gameover()` 是否能解析你的模式。当前 `endN` 取号方式对多位数结局不友好。
- `$gwin` 是否有对应编号。
- 新闻和模板是否有对应显示。
- RuleSet story key 是否匹配。
- 成就是否在 `check_end_achievement_rev()` 中处理。

## RuleSet 改动没生效

检查：

- 房间是否真的启用了该 RuleSet。
- 文件是否放在 `gamedata/ruleset/<ID>/cache/`。
- 任务扩展文件是否应该放在规则集根目录而不是 `cache`。
- 文件名是否带正确版本，例如 `resources_1.php`。
- `config()` 是否读取的是你以为的路径。

RuleSet 的 PHP 函数覆盖不是完整通用模块系统，不能只看配置里的 `override_modules`。

## 数据库报错

常见原因：

- 没有运行安装 SQL。
- 表前缀和 `config.inc.php` 不一致。
- 新字段没有加到所有相关 SQL 文件。
- 当前房间表和全局表混淆。
- SQL 字符串拼接时忘记引号。
- 直接把数组/JSON 拼进 SQL 没编码。

表前缀：

- `$gtablepre`：全局用户/房间等表。
- `$tablepre`：当前房间内玩家、地图物品等表。

## 改完后先跑哪些检查

最低限度：

```bash
php -l 被你改过的php文件
```

如果改了多个 PHP 文件：

```powershell
Get-ChildItem -Recurse -Filter *.php | ForEach-Object { php -l $_.FullName }
```

人工测试清单：

- 能打开首页。
- 能登录/入场。
- 能移动和搜索。
- 新资源能出现。
- 新道具能拾取/使用/丢弃。
- 战斗不白屏。
- 死亡和结局不白屏。
- 模板没有未闭合标签或按钮提交错命令。
