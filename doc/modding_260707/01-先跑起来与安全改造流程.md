# 01 - 先跑起来与安全改造流程

本章解决三个问题：怎么启动游戏、改文件前要知道哪些规则、改完以后怎样确认不是自己把项目改坏了。

## 最小启动方式

在项目根目录运行：

```bash
php -S localhost:8080 -t .
```

然后浏览器打开：

```text
http://localhost:8080/install.php
```

初始化完成后再进入游戏主页。数据库配置在 `config.inc.php`，表结构在 `gamedata/sql/`，完整安装 SQL 主要看：

```text
gamedata/sql/all_forInstall.sql
```

如果你是本地临时改造，不一定要先理解所有数据库表；但至少要知道玩家、房间、道具、新闻、用户成就这些数据不是存在 PHP 文件里，而是进了 MySQL。

## 每次改造前先做什么

建议按这个流程来：

1. 先确认当前游戏能打开。
2. 只改一个目标相关文件。
3. 如果改的是 PHP 文件，立刻跑 `php -l 文件名`。
4. 如果改的是资源生成类文件，重新开一局或新房间测试。
5. 如果改的是模板，必要时清理 `gamedata/templates/` 里的编译缓存。
6. 如果改了数据库结构，明确记录 SQL 变更和已有房间是否需要迁移。

语法检查示例：

```bash
php -l gamedata/cache/npc_1.php
php -l include/game/item.special_effect.php
```

批量检查可以用：

```bash
find . -name "*.php" -exec php -l {} \;
```

在 Windows 没有 `find` 时，可以用 PowerShell：

```powershell
Get-ChildItem -Recurse -Filter *.php | ForEach-Object { php -l $_.FullName }
```

## 文件编码非常重要

PHP 文件建议保存为：

```text
UTF-8 无 BOM
```

带 BOM 的 PHP 文件有时会在 `<?php` 之前输出不可见字符，导致白屏、登录失败、下载页面、`headers already sent` 或模板提前输出。以前反复遇到的“白屏先看是不是 UTF-8 with BOM”就是这个问题。

尤其注意这些文件：

- `config.inc.php`
- `include/common.inc.php`
- `include/game/*.php`
- `gamedata/cache/*.php`
- `gamedata/ruleset/*/cache/*.php`

如果只是改 `.htm` 模板，BOM 问题通常没 PHP 文件严重，但仍建议统一 UTF-8 无 BOM。

## 项目入口大概怎么走

常见请求流程如下：

```text
index.php / valid.php
  -> include/common.inc.php
  -> 载入配置、数据库、资源、规则集
  -> 进入大厅、注册、创建角色或加入游戏

game.php
  -> include/common.inc.php
  -> include/game.func.php
  -> 读取当前玩家 pdata
  -> 处理玩家状态、装备、套装、任务提示
  -> include template('game')

command.php
  -> include/common.inc.php
  -> 根据 mode 和 command 分发行动
  -> 移动、搜索、战斗、物品、商店、安全箱、任务、技能等
  -> 写回玩家数据并刷新界面
```

所以你看到某个按钮没反应时，通常要顺着三处找：

- 模板里按钮提交了什么 `mode` / `command`
- `command.php` 对这个命令有没有分支
- 分支里调用的函数在哪里实现

## 几个核心目录

| 路径 | 用途 |
| --- | --- |
| `include/common.inc.php` | 每次请求几乎都会先进这里，负责初始化 |
| `include/global.func.php` | 模板、配置路径、JSON 兼容、输入过滤等基础函数 |
| `include/game.func.php` | 游戏界面刷新、玩家状态刷新、公共游戏逻辑 |
| `include/game/` | 物品、战斗、移动搜索、社团技能、任务等主要逻辑 |
| `gamedata/cache/` | 默认规则下的资源配置 |
| `gamedata/ruleset/` | RuleSet 资源覆盖和特殊规则 |
| `templates/default/` | 默认模板 |
| `templates/nouveau/` | Nouveau 模板覆盖，不存在的模板会回退 default |
| `gamedata/templates/` | 模板编译缓存，不要手写这里 |

## 改完为什么没生效

资源和模板的生效时机不一样。

地图物品、商店、NPC 等很多资源是在一局游戏初始化时写入数据库的。你改了 `mapitem_1.php`，旧局里已经生成的地图物品不会自动重建，通常要新开一局测试。

模板 `.htm` 会被编译成 `gamedata/templates/*.tpl.php`。如果 `tplrefresh` 关闭，或者缓存文件时间更新，你改模板可能看不到效果。测试模板时可以临时打开刷新，或者删除对应编译缓存。

RuleSet 会优先读 `gamedata/ruleset/<规则集>/cache/` 下的资源。你改了默认 `gamedata/cache/`，但当前房间启用了 RuleSet，就可能完全没读到你的改动。

## 常见文件头

大多数 PHP 逻辑文件应当这样开头：

```php
<?php

if (!defined('IN_GAME')) {
    exit('Access Denied');
}
```

这表示文件不允许被浏览器直接访问，只能在游戏初始化后被包含。直接访问这类文件看到 `Access Denied` 是正常现象。

## 如何记录自己的改动

项目要求改代码时在 `doc/` 下写变更记录。格式建议：

```text
doc/YYYYMMDD-HHMMSS-change-description.txt
```

内容写两件事就够：

- 中文说明：改了什么，为什么改。
- English summary: what changed and why.

资源改造也建议这样做，因为几个月后你很可能已经忘了某个 NPC 为什么有那串 `clbpara`。
