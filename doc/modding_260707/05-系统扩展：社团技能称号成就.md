# 05 - 系统扩展：社团技能称号成就

本章讲四个经常被改造者问到的系统：社团、社团技能、头衔、成就。它们都不是“只在一个配置文件里加一行就全自动完成”的系统，但都有可以照抄的路径。

## 社团是什么

社团字段是玩家/NPC 的 `club`。显示名在：

```text
gamedata/cache/resources_1.php 的 $clubinfo
```

选择和初始化逻辑在：

```text
include/game/clubslct.func.php
```

技能配置在：

```text
gamedata/cache/clubskills_1.php
```

## 新增一个社团的步骤

假设要新增社团 `23 => '测试社'`。

### 1. 加显示名

在 `resources_1.php` 的 `$clubinfo` 加：

```php
23 => '测试社',
```

### 2. 让玩家能选到

`clubslct.func.php` 里有选择池。普通社团和特殊社团不在同一个列表。

常见函数：

```php
valid_getclublist_t2()
valid_getclublist_t1()
```

如果不把新编号加入选择池，玩家正常创建角色时看不到它。也可以不加入选择池，只让道具、头衔、剧情或管理员授予。

### 3. 决定入场基础奖励

`updateskill()` 里对部分社团有写死的基础加成，例如武器熟练、金钱、属性等。

如果新社团只靠技能，不需要基础加成，可以不加。若要入场加属性，就要在这里写分支。

### 4. 配技能列表

在 `clubskills_1.php` 的 `$club_skillslist` 加：

```php
23 => Array('s_hp', 'test_skill'),
```

`updateskill()` 会按这个列表给玩家注册技能。

### 5. 定义技能

同文件的 `$cskills` 里定义 `test_skill`。如果只是被动、展示或复用已有事件，配置可能够用；如果是全新主动技能或战斗机制，还要写逻辑。

### 6. NPC 使用

NPC 可以直接写：

```php
'club' => 23,
'clubskill' => array('test_skill'),
'clubskillpara' => array('test_skill' => array('level' => 1)),
```

NPC 不一定走和玩家完全一样的选择流程，所以给 NPC 技能时要确认 `customtclubskill()` 或 `changeclub()` 的使用方式。

## 社团技能配置在哪

文件：

```text
gamedata/cache/clubskills_1.php
include/game/revclubskills.func.php
include/game/revclubskills_extra.func.php
```

`clubskills_1.php` 里有一段比较详细的注释，列出技能字段。常见字段：

| 字段 | 含义 |
| --- | --- |
| `name` | 技能名 |
| `tags` | 标签，如被动、主动、玩家限定等 |
| `desc` | 描述 |
| `bdesc` | 战斗内描述或补充描述 |
| `maxlvl` | 最大等级 |
| `cost` | 升级消耗 |
| `input` | 是否需要按钮/输入 |
| `status` | 是否显示状态 |
| `effect` | 一些可配置效果 |
| `events` | 事件钩子 |
| `vars` / `svars` / `pvars` | 技能变量 |
| `unlock` | 解锁条件 |
| `lostevents` | 失去技能时触发 |

技能数据最终存在玩家 `clbpara` 中。

## 技能什么时候只改配置就够

通常够用：

- 给社团挂已有技能。
- 调整已有技能数值。
- 改技能名、描述、等级、消耗。
- 让 NPC 拥有已有技能。
- 使用已有事件字段实现同类效果。

通常不够：

- 新主动技能要点击按钮执行。
- 新技能要在战斗某一步改变公式。
- 新技能要在搜索、移动、死亡、任务、结局时触发。
- 新技能要有新的模板 UI。

主动技能命令通过 `command.php` 的 `revskpts` 分支进入，常见处理在 `revclubskills_extra.func.php`。战斗技能要看 `revattr.func.php`、`revcombat_extra.func.php` 里是否已有钩子。

## 技能模板

技能显示模板在：

```text
templates/default/skill_*.htm
templates/default/skill_temp.htm
```

如果某个技能没有专用模板，系统可能使用通用模板生成显示。需要复杂按钮、下拉框或状态面板时，要写对应模板和命令处理。

## 头衔是什么

头衔不是社团。头衔属于用户资料，玩家入场时可以选择一个昵称头衔，它会影响显示，也可能带入场奖励。

配置：

```text
gamedata/cache/titles_1.php
```

逻辑：

```text
include/game/titles.func.php
valid.php
include/messages.func.php
include/game/itemplace.func.php
```

`$titles_list` 定义编号到名称：

```php
$titles_list = Array(
    11 => '寻星者',
);
```

`$title_desc` 定义展示样式、说明、tooltip：

```php
$title_desc = Array(
    11 => Array(
        'class' => 'lime',
        'title' => '头衔说明文本',
    ),
);
```

## 头衔入场奖励：`title_valid`

同一个 `titles_1.php` 里还有 `$title_valid`。玩家在 `valid.php` 入场时会读取当前选择的头衔奖励。

例子：

```php
$title_valid = Array(
    11 => Array(
        'wk' => '[:+=:]50',
        'wep' => '『寻星勇者』',
        'wepk' => 'WK',
        'wepe' => 90,
        'weps' => 35,
        'wepsk' => 'd',
    ),
);
```

这里表示：

- 入场斩熟 `wk` 加 50。
- 入场武器变成 `『寻星勇者』`。

支持的运算符写法：

| 写法 | 含义 |
| --- | --- |
| `[:+=:]50` | 原值加 50 |
| `[:-=:]50` | 原值减 50 |
| `[:*=:]2` | 原值乘 2 |
| `[:/=:]2` | 原值除 2 |

注释里说“所有 player 表登记过的合法字段都可以写”，但实际使用时要谨慎。给物品栏奖励时要同时写完整字段，如 `itm6/itmk6/itme6/itms6/itmsk6`。如果只写 `itm6`，道具名有了，类型和效果可能是空的。

`clbpara` 可以作为数组写入，但要确认不会覆盖玩家已有关键状态。

## 怎样给玩家发头衔

旧式函数：

```php
get_title('寻星者', $username);
```

它会在 `$titles_list` 里找名称，再转换成新格式存进用户 `nicksrev`。

成就函数里大量使用 `get_title()`。管理员用户列表也能添加/删除头衔。

新增头衔时至少要做：

1. 在 `$titles_list` 添加编号和名称。
2. 在 `$title_desc` 添加说明和样式。
3. 决定是否在 `$title_valid` 添加入场奖励。
4. 找一个获取途径：成就、道具、剧情、管理员或其它逻辑。

只写 `$titles_list` 不会让玩家自动获得它。

## 成就配置

文件：

```text
gamedata/cache/achievement_1.php
include/game/achievement.func.php
```

主要配置：

| 变量 | 用途 |
| --- | --- |
| `$ach_type` | 成就大类 |
| `$diary_type` | 日志/图鉴分类 |
| `$hidden_ach_type` | 隐藏成就分类 |
| `$ach_list` | 成就列表 |

成就条目常见字段：

| 字段 | 含义 |
| --- | --- |
| `lvl` | 阶段阈值 |
| `name` | 成就名 |
| `lvlname` | 阶段名 |
| `request` | 要求说明 |
| `desc` | 完成描述 |
| `title` | 完成后给的头衔 |
| `c1` / `c2` | 奖励货币或点数相关字段 |

玩家实际完成状态主要存在用户表 `achrev`，是 JSON 风格数据。旧字段 `achievement` 仍有历史兼容痕迹。

## 新增成就不是只改配置

配置只决定“成就是什么、怎么显示、完成后奖励什么”。触发时机在逻辑里。

常见触发函数：

```text
check_mixitem_achievement_rev()
check_end_achievement_rev()
check_battle_achievement_rev()
check_item_achievement_rev()
check_misc_achievement_rev()
check_nums_achievement()
```

如果你新增的成就能复用已有统计，例如“合成某个道具”“获得某个结局”“击杀数达到某值”，可能只要加配置并确认现有函数覆盖。

如果你新增的是“第一次在灵子视界中钓到某物”“用某技能救下 NPC”，就需要在对应逻辑点调用：

```php
done_achievement_rev($ach_id, $level, $username);
```

或先更新计数，再检查阶段。

## 成就和头衔的关系

很多头衔通过成就发放，但两者不是同一个系统。

新增“完成成就给头衔”的路径：

1. `titles_1.php` 加头衔。
2. `achievement_1.php` 的成就阶段里写 `title`。
3. `achievement.func.php` 的触发函数在达到条件时调用完成逻辑。

如果触发函数没有覆盖这个成就，配置里的 `title` 不会凭空发出去。

## 称号卡和技能书

资源里有一些道具看起来像“称号卡”或“技能书”。它们通常通过 `itmk` 和处理器实现：

- 技能书多走 `item.skillbook.php`。
- 称号卡可能是特殊道具，具体要看道具名、`itmk`、`itmsk` 和处理文件。

如果要做“使用道具获得头衔”，最稳的办法是找已有称号卡，追到它的 item handler，再照着加分支。

## 给 NPC 特殊能力的三档做法

第一档：只改资源。

```php
'clubskill' => array('s_hp', 'some_existing_skill'),
```

适合让 NPC 继承已有社团技能。

第二档：复用已有特殊参数。

有些 NPC 或道具会通过 `clbpara`、`itmpara` 标记特殊状态。可以照着同类 NPC 写。

第三档：新增逻辑。

如果要“这个 NPC 第三回合变身”“死前召唤另一个 NPC”“被灵系攻击时回血”，通常要改：

```text
include/game/revcombat_extra.func.php
include/game/revattr.func.php
include/game/quest.func.php
include/game/item.npc.php
```

具体改哪里取决于触发时机：战斗前、命中后、死亡时、搜索时、道具使用时都不一样。
