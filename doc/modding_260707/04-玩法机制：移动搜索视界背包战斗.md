# 04 - 玩法机制：移动搜索视界背包战斗

本章讲玩家在局内最常接触的机制。重点不是复述界面文案，而是说明它们在代码里到底怎样运作，避免按错误理解去改。

## 行动入口：`command.php`

玩家大多数行动都进 `command.php`，再按 `mode` 和 `command` 分发。

常见分支：

| `mode` | 常见用途 |
| --- | --- |
| `command` | 移动、搜索、休息、钓鱼、物品主菜单、歌唱、特殊入口 |
| `itemmain` | 拾取、丢弃、交换、合成、道具详情、收入背包、切换武器 |
| `revcombat` | 新战斗系统的战斗准备 |
| `shop` | 商店购买 |
| `corpse` | 尸体操作、转移安全箱、种火收纳 |
| `quest` | 任务接受、拒绝、取消 |
| `revskpts` | 社团技能升级、切换、主动技能 |
| `dialogue` | 剧情选项和结束 |

模板按钮通常会设置这些值，然后提交到 `command.php`。新增按钮时不要只改模板，还要确认 `command.php` 有对应处理。

## 地点与移动

标准地点来自 `resources_1.php` 的 `$plsinfo`。禁区、随机安全区、地图显示等都围绕这些编号。

移动逻辑主要在：

```text
include/game/search.func.php
```

移动时会发生这些事：

1. 检查目标地点是否合法、是否禁区。
2. 扣行动消耗。
3. 更新玩家地点。
4. 清空搜索记忆。
5. 触发移动/搜索相关事件和任务 tick。

`$deepzones` 是深层区域列表，很多随机选点会避开它。新增地点时要想清楚它是不是普通地点、深层地点、隐藏地点。

## 搜索流程

搜索同样在 `search.func.php`。它不是简单“抽一个物品”。搜索会依次接触很多系统：

- 行动消耗。
- 天气、伤势、状态影响。
- 事件、平台、任务分配。
- 陷阱。
- 活人/NPC 遭遇。
- 尸体。
- 地图物品。
- 搜索记忆。

搜索结果不是完全由 `mapitem_1.php` 决定。你在地图放了物品，但玩家也可能先遇到 NPC、陷阱或尸体。

## 视界系统不是传统视野系统

旧文档里容易把它写成“视野/能见度系统”，但当前实现更接近“遭遇平面”。

相关字段：

```text
players.horizon
resources_1.php 的 $horizoninfo
```

当前主要视界：

| 编号 | 名称 |
| --- | --- |
| `0` | 通常视界 |
| `1` | 灵子视界 |

实际效果：

1. 搜索遭遇活人/NPC/尸体时，通常要求双方 `horizon` 相同。
2. 如果玩家在灵子视界中搜索不到对象，会提示周围没有同处于灵子视界中的对象。
3. 死斗阶段 `gamestate >= 50` 的玩家对玩家遭遇会忽略视界限制。
4. 切换视界会清空搜索记忆。
5. 移动/搜索消耗会变化：通常视界优先扣 SP，不够时可能扣 HP；灵子视界优先扣 HP，不够时可能扣 SP。

它不会自动做这些事：

- 不会让地图变成雾区。
- 不会改变玩家能看到的地点列表。
- 不会自动隐藏所有 UI 信息。
- 不会按距离计算可见范围。

如果你要新增一个“只有灵子视界能遇见的 NPC”，可以把 NPC 的 `horizon` 设为 `1`。但如果要做更复杂的“视野距离/侦察范围”，需要写新逻辑。

## 搜索记忆

搜索记忆存在玩家 `clbpara` 中，常见键类似 `smeo`。它用于记住某次搜索发现过的对象，避免玩家在拾取/处理前因为刷新或切换界面丢失上下文。

移动、切换视界等行为会调用 `lost_searchmemory()` 清掉记忆。

改搜索流程时要注意：如果你新增一个“发现后下一步处理”的对象，最好参考物品、尸体如何加入和清除搜索记忆。

## 行动消耗

配置主要在：

```text
gamedata/cache/gamecfg_1.php
```

常见变量：

| 变量 | 含义 |
| --- | --- |
| `$movesp` | 移动/搜索基础 SP 消耗 |
| `$movehp` | HP 兜底消耗相关值 |

实际扣法在 `calc_move_search_sp_cost()` 等函数里，还会受到视界、状态、天气或特殊技能影响。

## 物品栏和装备栏

玩家身上常见槽位：

| 槽位 | 含义 |
| --- | --- |
| `itm0` | 临时手牌/刚发现或待处理的道具 |
| `itm1` - `itm6` | 普通携带栏 |
| `wep` | 当前武器 |
| `wep2` | 备用武器 |
| `arb` | 身体防具 |
| `arh` | 头部防具 |
| `ara` | 手部防具 |
| `arf` | 足部防具 |
| `art` | 饰品 |

每个道具槽都有对应的 `k/e/s/sk/para` 字段。例如：

```text
itm3, itmk3, itme3, itms3, itmsk3, itmpara3
wep, wepk, wepe, weps, wepsk, weppara
```

写逻辑时不要只改名字，必须同步改类型、效果、耐久、属性和参数。

## 背包系统到底怎么运作

背包不是“容量按等级和装备计算”的系统。当前实现主要依赖带 `^` 特殊属性的背包道具。

相关文件：

```text
include/game/itembag.func.php
include/game/item.weapon.php
command.php
```

相关字段：

| 字段 | 含义 |
| --- | --- |
| `itembag` | 扩展背包内容，JSON |
| `getitem` | 临时待取物品，JSON |
| `itmnum` | 当前扩展背包数量 |
| `itmnumlimit` | 当前扩展背包容量上限 |

核心规则：

1. 道具 `itmsk` 含 `^` 时，被视为背包类道具。
2. 装备或携带背包时，容量上限通常由该道具的 `itme` 和 `itms` 取较小值决定。
3. 同一时间实际只围绕一个扩展背包容量工作。
4. 新背包更好时可能替换旧背包；旧背包内容会尝试保留或掉落。
5. 把普通物品收入背包时，会拒绝诅咒 `V` 和灵魂绑定 `v` 等物品。
6. 重量相关字段和函数存在，但当前主要重量限制逻辑没有真正启用。

因此，要新增一个 10 格背包，应该做的是新增一个 `itmsk` 含 `^` 的道具，并让它能被玩家获得。不是去改玩家等级公式。

示例：

```php
'便携收纳包', 'A', 10, 10, '^', ''
```

具体能不能作为饰品/装备触发，要看你放在哪个槽位和现有装备处理逻辑。

## 道具使用分发

主分发在：

```text
include/game/item.main.php
```

它会根据 `itmk` 和道具名/参数加载不同处理器，例如：

| 文件 | 常见用途 |
| --- | --- |
| `item.weapon.php` | 武器、防具、装备、背包类装备 |
| `item.recovery.php` | 回复品 |
| `item.poison.php` | 毒物 |
| `item.trap.php` | 陷阱 |
| `item.ammo.php` | 弹药 |
| `item.radar.php` | 雷达 |
| `item.cure.php` | 治疗 |
| `item.skillbook.php` | 技能书 |
| `item.enhance.php` | 强化 |
| `item.weather.php` | 天气道具 |
| `item.electronic.php` | 电子设备 |
| `item.quest.php` | 任务道具 |
| `item.ending.php` | 结局相关道具 |
| `item.special_effect.php` | 一些特殊效果 |
| `item.npc.php` | NPC 相关道具 |

新增普通恢复品、武器、弹药通常只需要资源。新增“点击后执行全新效果”的道具，必须在对应处理文件里写逻辑。

## 战斗系统概览

当前主要战斗走 `revcombat` / `revbattle` 体系。相关文件：

```text
include/game/revbattle.func.php
include/game/revcombat.func.php
include/game/revcombat.calc.php
include/game/revcombat_extra.func.php
include/game/revattr.func.php
gamedata/cache/combatcfg_1.php
```

`combatcfg_1.php` 主要放公式参数：

- 命中率。
- 伤害倍率。
- 姿态和策略修正。
- 天气攻击/防御修正。
- 地点、武器射程、属性倍率。

真正的特殊机制常在逻辑文件里：

- 某个属性在战斗中如何触发。
- 某个社团技能如何改伤害。
- 某个 NPC 如何进入特殊阶段。
- 任务战斗事件如何结算。

因此，加“攻击力 120 的新武器”是资源层；加“这把武器命中后复制敌人技能”是逻辑层。

## 姿态、策略、天气、异常状态

这些系统分散在几个地方：

| 系统 | 常见位置 |
| --- | --- |
| 姿态/策略名 | `resources_1.php` |
| 姿态/策略战斗修正 | `combatcfg_1.php` |
| 天气名 | `resources_1.php` 的 `$wthinfo` |
| 天气战斗影响 | `combatcfg_1.php` |
| 天气切换 | `system.func.php`、道具/技能/控制台逻辑 |
| 异常状态与死亡原因 | `state.func.php`、`resources_1.php` 的 `$stateinfo` |

新增天气编号时，只加名字不代表战斗和搜索都会受影响。必须确认对应公式数组和状态逻辑是否覆盖新编号。

## 尸体、安全箱和种火

尸体相关入口在 `command.php` 的 `corpse` 分支。玩家发现尸体后可以拾取、销毁、转移安全箱权限，部分社团/系统还会出现“种火”相关操作。

安全箱逻辑：

```text
include/game/depot.func.php
templates/default/sp_depot*.htm
```

地点入口由 `$depots` 控制。安全箱道具存在数据库表 `itemdepot`，不是存在玩家背包里。

种火逻辑：

```text
include/game/club22.func.php
gamedata/cache/club22cfg.php
templates/default/slidingpanel.htm
```

这属于比较复杂的社团专属系统。想复用时建议先完整读 `club22.func.php`，不要只复制模板按钮。

## 休息与钓鱼

休息、治疗、静养等状态会改变玩家 `state`，并由 `state.func.php` 维护。钓鱼是休息界面里的一个特殊流程：

```text
include/game/fishing.func.php
gamedata/cache/fishing.php
templates/default/rest.htm
```

钓鱼可获得道具和属性增长，并受地点、天气、时间段、钓竿影响。新增钓鱼内容时资源和逻辑都可能要改：资源决定鱼池，逻辑决定哪些地点允许钓鱼、钓竿如何加成。

## 判断改造位置的小表

| 需求 | 优先改哪里 |
| --- | --- |
| 多放几个地图道具 | `mapitem_1.php` |
| 让商店卖新东西 | `shopitem_1.php` |
| 新增普通 NPC | `npc_1.php` |
| 让 NPC 带已有技能 | `npc_1.php` 的 `clubskill` |
| 新增普通合成 | `mixitem_1.php` |
| 新增背包 | 资源里加 `itmsk` 含 `^` 的道具 |
| 新增特殊点击道具 | `item.main.php` 分发到的处理文件 |
| 新增战斗属性 | `$itemspkinfo` 说明 + `revattr`/`revcombat` 逻辑 |
| 新增视界玩法 | NPC/玩家 `horizon` + 搜索/移动逻辑 |
