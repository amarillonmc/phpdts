## 1. 结论与模式定位

**可以作为新的 RULESET 做出来，但工程量相当于在现有战斗系统上建立一个多人共享的探索模式，远不止复制 YELLOWKNIFE 资源和补几个隐藏地图。**

值得保留的核心体验是：一群人共享唯一一部电梯，可以分散在不同楼层探索；门外的空间随机、荒诞、风格断裂；探索有时间压力；返回电梯整理装备和交流；逐步接近上行、下行的叙事节点；最终自主脱出或继续冒险。

最需要先修正的假设：

1. **隐藏地图组只提供一部分移动约束，不是完整的楼层实例系统。** 遭遇、掉落、陷阱等多处按地点 pls 查询。不同楼层复用同一个 pls，会互相遇见、共享地面物品或踩到别层陷阱。
2. **原案编号不可直接使用。** 仓库建表脚本的 pgroup、pls 多为无符号 TINYINT；299、301—808 超出 255。NPC 类型 type 还是有符号 TINYINT，不能把素材编号 601 当 NPC 类型。
3. **现有“无月之影”不等于全面禁斗安全区。** 电梯需要独立的战斗、道具、异常及入侵例外规则。
4. **现有 end2/end3 不是个人脱出接口。** gameover() 会结束整个房间并触发全局优胜、成就、积分等流程。
5. **“5 秒到站”“不操作也逐渐死亡”需要服务器时钟推进。** 不能只在该玩家下一次 action 后检查，更不能按刷新次数扣血或掷入侵概率。
6. **共享电梯与个人倒计时存在直接冲突。** 若别人可以随时开走电梯、让它长时间被入侵锁住，楼外玩家可能在没有任何有效操作的情况下被判死。
7. **共享电梯与个人选择无尽也存在冲突。** 一人选择继续不应使其他乘客和留在别层的人永久失去脱出机会。
8. **素材不是可直接导入的资源。** 第二帖有 64 个地图模板、129 行物品、23 个 NPC／环境交互条目；大量道具只有名称，没有用途；不少 NPC 实际是需要独立状态机的事件。

### 建议的产品边界

- 正式模式代号：**ELEVATOR**；“电梯模式”继续作为暂定中文名。
- 基础资源：固定版本的 YELLOWKNIFE，经筛选后形成 ELEVATOR 自己的资源清单。
- 主要玩法：多人合作探索、资源交换、风险选择。**建议首个正式版本禁用玩家互相伤害**；对原案未明确的楼层 PVP 取舍，见第 9 节。
- 适配人数初值：1—8 人，1 人也能完成有限流程；不是从 300 人大房间参数直接缩小。
- 有限段体验目标：到达一个普通脱出节点约 12—20 分钟；完整探索一侧终点约 25—40 分钟。属于测试目标，不是当前代码能保证的时长。
- 内容目标：全部八池、七类入侵、上下两端节点、独立个人结算、可继续的无尽段。
- 不把原案的里设定直接写进公开帮助。玩家能看见的是空间、人物表现和可观察的线索，真相说明保留在内部设定栏。

## 3. 源码事实：能借用什么，哪些不是现成功能

### 3.1 RULESET 与资源加载

- config() 先查当前规则集 cache 中指定版本，再找其版本 1，然后回退到公共 gamedata/cache。**缺文件不会自动继承 YELLOWKNIFE，而是回到公共默认资源。** 必须复制受控资源或新增明确的继承方案，不能仅写“base=YELLOWKNIFE”就认为生效。[S01]
- 当前通用加载器寻找规则集 include/ruleset.func.php，兼容旧 ruleset_functions.php。override_modules 不能自动让任意同名 PHP 函数被替换。[S02]
- 模板函数按玩家模板目录及默认模板回退，没有现成的 ELEVATOR/templates 自动寻址；default、nouveau 都需要接入口和检查。[S03]
- 普通配置、规则集根目录的任务资源、规则集根目录的 story_1.php 使用不同读取路径，不能全扔进 cache。[S04]
- 可以借用 RAID 的分文件组织、请求锁、个人账本、一次性结算标记，以及莱卡的道具标记、状态效果和渲染做法；不要把这两个模式的具体积分、天气或剧情副作用一起复制。[S05]

### 3.2 空间、编号与实体

- check_can_move()/move() 根据 pgroup 取隐藏地点列表；但 discover() 的 NPC／玩家、地图物品、陷阱检索并没有形成统一的“房间＋楼层实例＋地点”隔离接口。[S06]
- 玩家、地面物品、陷阱地点字段的脚本类型为无符号 TINYINT；players.pgroup 同样如此。NPC type 是有符号 TINYINT；运行实体 pid 与 NPC 类型及模板编号是不同概念。[S07]
- YELLOWKNIFE 已有隐藏地点 101—103、111—114。原案湾城的 101 等如直接加入，会覆盖或混用已有地点语义。[S08]
- 组内目前可直接选任意地点，不自带“从东侧接近炮台”“只能经过上一格”这类有向邻接结构。需要新增地图连通图和移动来源记录。[S06]
- 仓库、商店、地图修正、剧情地点判断、雷达、噪音、新闻、尸体定位等许多地方直接依赖 pls。地图 ID 扩容或动态化需要完整追踪，不能只改 players 表。[S09]

### 3.3 时间与多人状态

- 公共初始化在非聊天 HTTP 请求中取得 process.lock、读取房间、推进禁区与阶段，然后释放锁。它不是专门的电梯定时服务。[S10]
- command.php 已有读玩家行前的请求钩子、动作前钩子、动作后及保存后钩子。动作前钩子位于部分对话／冷却判定之后；若把时间推进只放这里，会被某些不执行动作的路径漏掉。[S11]
- 玩家激活 valid.php 与普通指令不是同一个临界区。init_playerdata 的钩子更接近读取后初始化，不是专用“加入正在移动的电梯”的原子出生接口。[S12]
- gamevars 通过 JSON 整体读写，仓库建表定义为 TEXT；不是无限容量的蓝图数据库。MyISAM 表不能假设 SQL 事务能自动回滚一组玩家、掉落和房间更新。[S13]

### 3.4 战斗、死亡、终局

- 实际主要战斗路径是 revbattle → revcombat → revattr；同时仍有道具、陷阱、天气、事件和自然死亡等路径。仅修改旧 battle/combat 函数不够。[S14]
- 无月之影的危险区名单主要限制部分 NPC 移动，并不是通用“禁攻击”标志。其地图 0 甚至存在攻击修正。电梯安全区必须明确新增。[S08、S14]
- 普通中毒／烧伤等多处在移动、搜索时结算；不能保证原案所说的真实时间逐步耗死。[S06、S15]
- gameover() 不仅设 winmode，还会收集胜者、写全局 winners、发新闻、调用积分／成就等流程、把 gamestate 置 0。个人脱出必须走另一层生命周期。[S16]
- 公共流程有无人参赛、停止激活、连斗、反挂机、最后存活及零存活收尾。已有 ruleset_should_auto_gameover 不能覆盖所有阶段分支；common 的零存活还会强制结束。[S10]
- RAID 的“撤离”证明个人结束参与可以实现，但它采用本模式特定的离场／死亡展示和计分方式，不能直接拿来当电梯的“活着逃出”。[S17]

## 4. 建议版完整玩法规格

本节是**建议修订版**，不代表原案已有这些决定。数值均为测试起点，后续依据第 8 节数据调整。

### 4.1 一局的流程

1. 创建 ELEVATOR 房间，锁定资源版本、随机种子和规则版本。
2. 开局生成有限段蓝图、起点与电梯，清除本模式不启用的普通局内容。
3. 玩家加入车厢安全候乘位，阅读简短操作说明，获得标准起装。
4. 乘客请求上／下行；电梯停靠、开门，玩家自由决定是否进入该层。
5. 楼层探索包括搜索、战斗、环境交互、收集线索；每人有自己的暴露时间。
6. 返回电梯口登记叫梯，进入候梯保护；可取消保护继续探索。
7. 登车后整理装备、交易、阅读已取得的资料；电梯可能发生有预告的入侵。
8. 到达节点，玩家可独立脱出。其他人继续。
9. 抵达一侧终点，可普通脱出、完成特殊条件后脱出，或明确选择无尽。
10. 所有仍参与的人完成集合与选择，才开启该方向无尽；房间只保留一部共享电梯。
11. 全部玩家已脱出／死亡／放弃，或达到房间封存条件，归档并结束房间。

**不使用普通“最后剩一个人就获胜”的目标。** 单人生存只是继续探索的合法状态。

### 4.2 楼层坐标与方向

| 层段 | 建议逻辑坐标 | 功能 |
| --- | --- | --- |
| 起点 | 0 | 教程与第一次方向选择，无正常刷资源 |
| 上行普通层 | +1…+6 | 湾城、记忆、荒诞等较高权重 |
| 上行终点 | +7，节点 attic | 阁楼剧情、普通／特殊脱出、继续上行选项 |
| 下行普通层 | −1…−6 | 电掣、废土、钻探主题逐渐增强 |
| 下行终点 | −7，节点 fireseed | 大种火非战斗对话、离开或继续 |
| 无尽上／下 | +8…／−8… | 增量生成，明确越界后不回有限段 |

- 有限段允许上下反向移动，也允许回访已生成楼层；不是每回到同一层就重新抽奖。
- 普通脱出节点初值放在 ±3、±5，两端 ±7 都提供离开机会。
- “错过节点”在有限段只表示本次没有下梯／没选择离开，**不永久删除该玩家的退出资格**。永久承诺发生在进入无尽的确认点。
- 这些坐标用于距离与 UI，不作为 pgroup 或 pls。199、200、299 等原案编号作为草案标注废止。
- 实際点数采用“2—5 个内容点＋独立电梯口”。大种火层为一个内容节点加必要的出入／交互界面；不得生成随机战斗。

### 4.3 单部电梯状态与操作

| 状态 | 允许的操作 | 转移条件 |
| --- | --- | --- |
| 停靠开门 | 登车、下车、整理、叫梯、提出相邻行程 | 开门最短时间届满，存在可执行请求 |
| 关门预告 | 已有乘客整理、取消自己尚未提交的下车动作 | 5 秒服务器倒计时完成；已登记的站台登车请求先结算 |
| 运行 | 车内整理与有限交互、登记下一次停靠请求 | 到达时间；不能瞬移下车、改写当前目的地 |
| 入侵预告 | 阅读规则、选择准备、处理参与对象 | 预告时间完成 |
| 入侵进行 | 当前事件允许的战斗／交互 | 成功、选择、失败或硬性超时 |
| 恢复 | 发放结果、清除事件锁、恢复待处理队列 | 幂等提交完成 |
| 封存 | 查看个人结果／归档 | 无后续游戏动作 |

**调度建议：**

- 任意乘客仍可按上／下，但按钮产生请求，而不是立即覆盖所有人的路线。
- 同一楼层的叫梯合并；同一玩家只有一个有效叫梯；重复点击不改变排队顺序。
- 已进入运行的目的地不改变。当前行程结束后，已承诺的接人请求优先于新探索请求。
- 多个接人请求按登记顺序处理；同一顺路停站可合并。用最大等候承诺避免远层永远被饿死。
- 空车也能按叫梯队列运行；车内所有人死亡或脱出，不得让楼外活人永远等不到车。
- 已进入候梯保护且仍在电梯口的玩家可预先勾选自动登车；抵达时由服务器完成，避免“网页没刷新，门就关了”。
- 当前停层、目的层、剩余行程、前序停站和入侵锁定状态公开；不公开未生成楼层的完整内容。
- 车厢内部地点固定，乘客在运行期间始终位于车厢。移动的是电梯的逻辑楼层，不是把所有乘客先改到目标层的野外地点。

**时间公式：**

原案的距离公式只适用于静止、无排队、无入侵的车。完整估计为：

~~~text
预计接到时间
= 当前行程剩余时间
+ 前序已承诺行程的距离耗时
+ 前序停站／关门耗时
+ 到本人楼层的距离耗时
+ 已知入侵剩余锁定时间
~~~

初始每层运行 3 秒、关门 5 秒、最低停站 8 秒。所有时间由服务器给出；未知事件不能伪装成精确 ETA，可显示“至少 N 秒／入侵处理中”。

### 4.4 个人暴露预算、候梯与断线

这是对原案最关键的公平性修订。

- 玩家首次离开某层电梯口保护区，获得该层的个人暴露预算，建议 150 秒起步，深层下降到 100 秒下限。
- 预算按**实际时间**消耗，战斗、搜索、翻包、正常离线均计入。刷新、无效命令、客户端改时钟不会改变预算。
- 每层对每人累计消耗；回车厢再下到同层不刷新预算，防止反复上下车重置。
- 返回本层电梯口并登记有效叫梯后，进入“候梯保护”：该层暴露和该模式的侵蚀伤害暂停。
- 保护期间不能搜索、战斗、休息刷恢复、向外投掷／攻击；只能查看背包、阅读日志、取消候梯。自行离开立即继续原预算。
- 已经耗尽预算但尚存活，也允许抵达电梯口取得保护；迟到的损伤不会因此被治疗。
- 候梯保护暂停本模式的空间侵蚀；既有普通中毒等按第 4.7 节暂停负面伤害与行动副作用，不自动净化，不能出现 UI 称“安全”却继续后台扣死。
- 没到电梯口仍继续停留者，进入递增侵蚀：例如每 5 秒损失最大生命的 5%，每累计 20 秒升一档，上限 20%／5 秒。此处是专属危害，不受普通毒抗解除。
- 达到危险阈值前给出 30 秒、10 秒、侵蚀开始提示。服务器按时间段累计结算，不能因断线一次性重复结算相同时间。
- 断线不重置预算，不产生额外惩罚；重新连接先显示服务器已结算的状态。非入侵参与者在车厢或候梯状态中断线保持安全，不因别人操控电梯被投入野外。已经登记参与的入侵按既定截止和失败规则结算，不能靠断线免除已经发生的攻击或代价。
- 服务器故障引发的长时间不可用采用“运行中断”结果，不能把停服时间作为玩家失误。需要服务心跳与恢复策略。

这样保留“探索必须及时返回”，又不把远处乘客引发的入侵变成无法反制的处决。

### 4.5 加入、离场与重新加入

- 建议开局前和有限段前 10 分钟允许激活；无尽段关闭新激活。时间窗可调整。
- 新玩家先进入当前电梯的安全候乘位。运行中等到站、入侵中等事件结算，不直接作为本次事件目标。
- 不允许利用新号进入车厢反复创造物资：每账户每局一次起装；起装暂不可向他人转赠，或通过本局贡献解除绑定。
- 已脱出、死亡或放弃者不能在同一局重新激活取得第二套起装；可以旁观。
- 房间退出与游戏内脱出是不同操作。通过房间管理退出，需要清理叫梯、乘客、交易和事件参与资格，并记录“放弃／离场”，不能只改 users.roomid。
- 新人出生在原案所说的楼层电梯口可作为后续可选规则，但必须给等价保护和保底补给；不建议作为默认，避免在深层和入侵中刚激活就暴毙。

### 4.6 楼层生成、消耗与回访

有限段开局预生成：

- 地点模板引用、邻接关系、每点物品预算、NPC／事件模板引用、种子、风险等级、脱出节点标识。
- 同一层允许跨池混合，但所有点必须能抵达电梯口；至少一个可用补给渠道；事件前置物不能只出现在永远无法到达的后续层。
- 每层 0—2 个普通战斗／交互槽位；不是把某主题池的全部 NPC 自动投放。剧情终点有明确例外。
- 稀有怪、镜像、复制水龙头等带专用风险成本，不与其他必杀陷阱无检查叠加。
- 地面物资为房间共享，但最低生存补给按玩家首次有效到访发放一次，保证晚到玩家仍可完成该层。
- 故事线索记入个人笔记，不要求 75 种 X 道具全部占用六格背包；重要可交易证据仍可保留为实体。
- 地点、库存、已完成事件、死亡 NPC、尸体和陷阱状态在回访时保留。玩家不能通过叫梯、离开地图或断线把战利品重刷。
- 谜语／交易等个体事件奖励每人一次；共享机关每局或每个楼层实例一次。定义清晰的作用域。
- 无尽使用固定种子派生每个逻辑楼层，首次访问时物化，后续不重新 roll。
- 有限段允许归档后再载入旧层；无尽越过不可回头边界后，只有不存在玩家、从属 NPC、事件、未结交易及必须保留尸体等活跃引用的旧层才可回收。
- 模板重复时更换组合、条件和情报，而不是单纯把同一场景文字再播一次。叙事首次阅读与机械再次出现分开计数。

### 4.7 战斗与安全区规则

**默认建议：所有楼层禁止 PVP，普通楼层允许 PVE；车厢与候梯区禁止自由攻击，仅当前入侵指定的对象可按事件规则战斗。**

- 玩家对玩家的普通攻击、追击、协战、陷阱、投毒、远程伤害、强制位移全部服从同一个规则判断。
- “不可攻击 NPC”不是把 HP 设得很高，而是不进入可攻击实体列表，或由服务端明确拒绝攻击。
- 入侵敌人白名单包含事件 ID、实体 pid、允许参与的玩家快照；事件结束后立刻失效。
- 常态车厢和候梯保护中，暂停既有普通负面状态的伤害及行动副作用，停止对应负面状态持续期的倒计时；离开后从剩余时长恢复，不追补保护期间伤害。此举不自动净化，也不把死疗等转伤为治疗的效果变成收益。BUFF 及模式专属效果仍按各自到期条件运行。入侵参与者承受的是本次事件明确授权的效果。
- 车厢不等于万能治疗室。允许正常道具治疗、限定商店补给；入侵锁定时禁止会绕过事件代价的保管箱／交易操作。
- 移动前后清理或重校验战斗目标、追击标记、协战、尸体窗口、搜索记忆和待拾取物。不能把楼层里的旧攻击按钮带到车厢继续使用。
- 普通楼层技能基本沿用 DTS，但传送、直接结局、全地图杀伤、外援、自动寻找所有 NPC 等能力采用 ELEVATOR 明确白名单。
- 初版不免费提供复活。若玩家持有本模式允许的涅槃／复活道具等能力，全部共用每人每局最多一次的模式额度；天气复活、自然死和战斗死也必须经此检查，不能绕过额度。未适配的复活来源先禁用或给社团替代能力，后续专属复活甲也不得追加独立次数。
- 复活建议恢复 30% 最大 HP、15% 最大 SP，位置为当前楼层受保护电梯口；车厢入侵死亡则在车厢中暂时退出本次入侵，不能立刻刷第二份奖励。不重置楼层库存／累计暴露，不取消无尽承诺，也不使已脱出者返场。已耗尽预算者若再次离开保护，仍从原侵蚀阶段继续；复活不是免费再探索整层。
- 种火、灵俑等从属实体也需要乘梯协议：跟随态随主人原子更新 pls、pgroup 和楼层实例，部署态留守并计入活跃引用；回收前可明确自动收回，不得静默删除。主人脱出、死亡或放弃时，按实体配置收回／清理和处理携带物；不能把它们留在旧层制造无主掉落。现有跟随只在普通移动／搜索链路调用，自定义上下梯不会自动获得这项能力。[S27]

### 4.8 七类入侵的完整规格

统一规则：不因一名玩家刷新而多抽一次；同一时间只有一个事件；开始时快照参与者；有预告、有终止时间、有失败分支；空车不生成等待玩家解题的事件。

**运行中入侵的推荐处理：**运行中只记录触发标记，在下一站到达、开门之前进入入侵预告；事件结束再正常开门。本版不在半层位置冻结列车，避免“入侵期间 arrival_at 是否仍推进”的歧义。若后续必须表现为半途停梯，需另存被暂停行程、剩余时间和恢复状态，不能只改一个 state 字段。

**参与与伤害：**预告开始时登记近期有活动的车内乘客，候乘新人、已结算者和已离线的安全乘客不加入本次名单；近期活动窗口初值 60 秒。预告结束冻结名单，之后断线不取消既有事件责任。战斗入侵默认每个登记乘客承受一次独立记录的开场冲击，随后与同一个共享敌人分别进行现有双方战斗；重复点击不会重放冲击。建议强制开场冲击最多损失 25% 最大 HP 且至少留下 1 HP，后续普通战斗可以致死。这是对原案可能致死的初见突袭的显式降低风险修订；若要保持完整致死原样胜者攻击，应改为玩家自愿选择的挑战。

**失败与奖励：**普通入侵战斗超时，活着的参与者受到一次有上限的故障冲击（建议不超过 15% 最大 HP、至少留 1 HP），无击破奖励，清理敌人并解锁；剧情执行者支付／留守按其专门代价结算。有效伤害、完成交互分别记贡献；奖励按参与和最低有效贡献发个人份额，不由最后一击独占，离线旁观者不取得战斗奖励。不得靠失败反复刷经验、金钱或同一份战利品。

| 入侵 | 触发倾向 | 新增机制 | 成功／失败／超时与奖励 |
| --- | --- | --- | --- |
| 钻探层回响 | 下行深层、关注度达到阈值 | 错误 NPC、合法战斗属性、乱码显示、禁止普通掉落表混入 | 击败获得日志线索及少量模式贡献；90 秒未解决则故障冲击后解锁，不无限卡车 |
| 缝隙中的窥视者 | 全层低频；与连续战斗互斥 | 只演出，不进入战斗列表；对参与者施加一次状态 | 约 10 秒结束；BUFF／DEBUFF 持续到下一次下梯完成或最长 120 秒，防挂机永久保留 |
| 电梯规则自我执行 | 中深层、携带违禁物、关注度 | 玩家选择自愿留守、支付专用物品、共同迎战；提交选择原子扣除 | 20 秒选择期，无响应默认迎战；自愿者被送至受保护电梯口，有后续叫梯权；不得无同意直接杀人 |
| 阁楼粉丝入侵 | 上行高层 | 签名、合影、选择题或礼物，个人完成标记 | 无战斗；超时按礼貌拒绝结束，不以未知梗处死新玩家；收藏或小额奖励 |
| 幻境碎片入侵 | 上行高层、明确危险预告 | 历史胜者快照标准化，受控首次攻击、多人对象分配、后续普通 PVE | 先手造成有上限的冲击，后续战斗可赢可败；只掉落审核过的映射奖励，不复制原人全部物品 |
| 幻境底层溢出 | 深层、异常物品携带 | 合法事件效果池、物品新增／丢失、属性变化、参与者个人选择 | 明示“触碰”或“避开”；丢失物品排除不可替代任务证据；溢出不会把数据库写成无效类型 |
| 乘客残影 | 曾访问区域、低压力时段 | 经过清洗的预制片段／历史行为摘要、与本局蓝图核对的情报 | 约 10 秒结束；提示必须实际可用，相关楼层已失效则改给替代信息；不回放真实私聊 |

**自愿留守的实际代价：**留守者落在当前层受保护电梯口，但在电梯完成一次抵达其他楼层的行程之前不能重新登车，也不能让本人的叫梯覆盖这段行程。事件结束立即执行该已公示行程，完成后恢复其正常接人优先级；期间不扣暴露。单人局不提供留守选项，使用支付或战斗分支。这样不会出现“选择留守后立即上同一部车，零代价解除事件”的循环。

初值：开局前两次停靠不出现强制战斗；事件结束后至少两次有效停靠或 60 秒不再触发战斗入侵；关注度每次完成新的有效行程增加，阈值参考 6，不能通过反复同层开关门刷事件。

停留、拥挤和诅咒是**调度权重**，不是各自都能单独立即触发一次。携带诅咒者下线／存物之后也必须按明确归属清理，不让已经排队的事件失去来源又永久锁住。

### 4.9 节点、谜语、个人结算与房间封存

| 模式内部结果 | 触发 | 玩家得到什么 | 是否结束整房间 |
| --- | --- | --- | --- |
| 生存脱出 | 在已抵达的普通或终点节点选择离开 | 个人成绩、已找到线索、普通脱出故事 | 否 |
| 锁解释放 | 终点完成对应特殊条件并选择离开 | 个人特殊结果与解锁记录 | 否 |
| 探索死亡 | 普通战斗／侵蚀等最终死亡 | 本局探索记录、死因，未兑现收益按规则损失 | 否，除非无人继续 |
| 无尽终止 | 无尽死亡或主动认输 | 已达到的深度、无尽成绩；认输不算脱出胜利 | 否，除非无人继续 |
| 中途离场 | 玩家主动退出房间／放弃有限段 | 记录已完成事实，无脱出胜利奖励 | 否 |
| 限时封存 | 达到开局已公示的模式时长上限，玩家仍存活 | 存活结束、保留已完成成绩，无脱出胜利奖励 | 是，统一归档 |
| 运行中断 | 管理员中止、服务故障、不可恢复状态 | 中断标志，不算战败，不发本次额外胜利奖励 | 根据原因 |
| 电梯封存 | 无参与者或正常时长上限 | 房间总结，包含每人的真实结果 | 是 |

- 原案 end2/end3 保留为故事表现上的候选标签；逻辑使用上述模式内部结果，不直接调用 gameover('end2') 处理个人。
- 在结算服务里先原子标记退出参与、取消队列／交易／事件资格、冻结成绩，再发放奖励和个人故事。重复提交只能读到已有结果。
- 不能简单 hp=0 后套“死亡”页面来表示活着离开，也不能 hp>0 而仍被所有存活查询算作在场玩家。
- 房间统计区分：已激活人数、仍参与人数、已脱出人数、死亡人数、车内人数、各层人数。更新公共存活判断的适配层。
- 大种火谜语未解开也可普通离开；特殊结局可要求本局两条不同来源的线索＋正确解析。线索要有替代获取渠道，不可纯抽不到。
- 阁楼的特殊条件建议是收集并理解若干本局回声，而不是必须知道真实玩家内梗。
- 原案未定义 end8：建议“电梯封存”作为房间收尾原因，不把全房间强制写成某一人的个人结局。与 RAID 的 end8 展示需要按规则集隔离。
- 默认不沿用普通胜率榜、赌局与跨局货币奖励。可保留模式内成绩；若需要账号长期奖励，另设限额且按个人结果发放，避免刷小房间。
- 排行建议分成有限段脱出与无尽深度两个榜，不用死亡才能终止的无尽结果拉低普通胜率。
- “有效探索深度”要求本人在该层完成一个非重复内容交互、一次有效击破或至少两次有效内容点搜索；仅在车厢路过、门口反复移动、重复读取已结算故事不计。具体门槛可调，但资格和去重必须先定义。
- 首版不提供任意乘客一键封存全房间；管理员中止与正常限时封存分开记录。正常达到时长上限不是服务故障，也不伪装成玩家死亡。

### 4.10 无尽承诺与结束边界

原案的“各人可继续”遇到单部电梯后，必须补一条集体边界规则：

1. 终点先让各人分别选择脱出或提出无尽提案；未选不能自动视为同意。
2. 提案窗口初值 120 秒。仍参与者有人反对或未回应，提案取消，继续有限段；不因有人发起提案而驱逐未回应者，不影响正常车厢／候梯的断线保护。相同提案设冷却，避免弹窗骚扰。
3. 全体剩余参与者同意后进入集合阶段，给出明确集合窗口和电梯接人路线。所有人须回到终点候乘区／车厢；有人未到、撤回或断线未完成最终确认，则取消此次无尽发车，保留有限段状态。
4. 全体完成最终确认“进入后不再有正常脱出节点”，才开始无尽。主动脱出者在每一步都先处理个人结算，不要求他们参加继续提案。
5. 进入后电梯仍可接回本次无尽段中的落后者。建议最多同时保持 8 个活跃楼层实例；到达预算上限先接人、结束可关闭事件并归档，不继续生成新的前沿。新前沿行程至少须满足所有仍参与者已上车或已结束参与；有人继续留守则暂不推进，直到其返回或全局时限封存，不能删除其楼层。
6. 正常玩法结束方式仍是死亡；补充“主动认输”用于用户退出，结果等同放弃当前挑战收益，不算普通脱出。这是对“只能死出去”的明确修订。
7. 无尽指内容可以继续生成，不承诺服务器永远保存无限量数据。设资源预算和最长会话保障；达到运行保护上限时按封存／中断记录，不伪造玩家死亡。
8. 建议有限段最长 60 分钟、无尽单次最长 90 分钟；这些是运营测试初值。接近上限时提前提示，并提供保存既有成绩的明确结束流程。

## 5. 状态与数据设计

以下是未来实现契约，不是本次新增字段。

### 5.1 三类编号必须分开

| 概念 | 示例 | 用途 |
| --- | --- | --- |
| 内容模板 ID | bay_101、void_mirror、intrusion_echo | 稳定素材身份，跨局重复使用 |
| 逻辑楼层坐标 | −6、+7、−23 | 方向、距离、深度、节点判断 |
| 运行时楼层实例／地点 ID | 本局实例 42，地点 10042 | 查询实体与库存，保证同房间实例隔离 |

**推荐完整方案：扩容地点相关字段，并为同一房间内每一个物化地点分配唯一 pls。** pgroup 对应运行时楼层组；车厢拥有独立固定组和地点。重复的“咖啡厅”模板在不同楼层有不同 pls。

这比立即给所有旧 SQL 都增加复合实例字段更适合当前“按 pls 检索”的代码；但仍需要补一致的空间校验，动态地点元数据，以及各入口对已失效地点的拒绝。

替代方案是保留有限数量槽位，将楼层映射到 0—255 内的安全编号并回收。它适合原型，**不适合不加限制地承诺多人分散＋无限回访**。有玩家、尸体、搜索记忆或事件引用的槽位不能复用；否则旧窗口会误操作新楼层。若不扩容，就必须把“最大活跃楼层数／不可返回”作为公开玩法限制。

### 5.2 房间级状态

建议 gamevars 只保留一个小型 elevator 命名空间：

| 字段类别 | 必须保存的内容 |
| --- | --- |
| 身份 | rules_version、content_version、round_epoch、seed |
| 电梯 | state、current_floor、from_floor、target_floor、departure_at、arrival_at、door_close_at |
| 调度 | 单调递增 revision、请求序号、合并后的有限长度叫梯队列 |
| 入侵 | event_id、模板 ID、阶段、开始／结束时间、参与者标识、冷却／关注度 |
| 生成 | 有限段蓝图引用、已物化区间、下一运行时 ID、资源预算摘要 |
| 结算 | 本局参与计数、封存标记、结果归档引用、结算版本 |
| 恢复 | last_advanced_at、当前操作 ID、需恢复的操作状态 |

不在 gamevars 里重复存储 64 地点文案、所有物品实例、所有旧楼层完整状态或长篇历史回放。

### 5.3 独立持久化内容

建议新增模式专用的持久化表／等价仓储，具体表名待实装统一：

- **楼层实例表**：按房间＋局次＋楼层实例唯一，存模板引用、图结构、物化状态与摘要。
- **事件状态表**：房间事件或个人事件作用域、参与者、选择、截止时刻、结算标记。
- **个人结果表**：玩家、局次、退出原因、深度、贡献、收藏摘要、奖励发放标记。
- **必要的运行操作日志**：生成、集体移动、结算等跨多表更新的开始／完成标记，用于崩溃恢复。
- 地面物品／NPC 尽量仍使用现有实体表，但必须带可追溯的楼层实例来源或能由唯一 pls 回查。新的长文本状态只在自己的仓储保存。

模式专用表可采用支持事务的存储；**仅新增 InnoDB 表并不能让仍在 MyISAM 的 players/mapitem 更新自动变成跨表事务。** 后续实现必须二选一：一并迁移涉及原子动作的表，或保留请求互斥＋可恢复操作记录。测试要覆盖进程在中途退出。

### 5.4 玩家级状态

clbpara['elevator'] 保存：

- mode_status：候乘、车厢、探索、候梯、已脱出、死亡、认输。
- 当前楼层实例、当前地点、上一次来源地点、参与局次。
- 各已访问楼层的剩余暴露预算或其仓储引用、最后计时时刻、侵蚀阶段。
- 当前事件参与 ID、个人事件／线索完成记录、待展示故事。
- 起装领取标记、个人贡献、收藏、最高到达与有效探索深度。
- 特殊物品所有权／携带诅咒，不使用道具中文名称当唯一身份。
- 结算结果 ID、幂等标记、客户端最近确认的状态版本。

长期无尽不能让 clbpara 的访问历史无限膨胀；保留摘要、近期状态和单独归档引用。

### 5.5 动作与时间的服务端约束

每个有效请求按统一顺序处理：

~~~text
取得与公共流程一致的锁／事务边界
→ 读取最新房间和玩家状态
→ 按服务器时间推进已到期事件
→ 按动作作用域校验局次、相关修订号、玩家是否仍参与、位置、目标与事件身份
→ 执行一次动作
→ 原子消耗物品／改变位置／结算奖励
→ 保存房间、玩家、事件与操作完成标记
→ 释放锁，返回当前可见状态
~~~

- request_id／操作 ID 防止同一动作因重试重复执行；不能只信浏览器禁用按钮。
- 版本校验按作用域进行：上下梯检查停站／路线版本，事件选择检查 event_id 与阶段，楼层搜索检查实例代次与位置。全局 revision 用于界面同步，不应让别层有人叫梯就使本人的普通搜索／吃药失败。
- 电梯到达与登车、死亡与脱出、两个玩家支付同一公共代价、两次领取最后一个库存都需要明确唯一赢家或合并策略。
- 同一服务器时刻的建议顺序：先结算到该时刻为止但不含同秒新段的已发生伤害，再处理到站／事件结束，再处理截止前已经被服务器接受的候梯／登车／脱出请求，最后执行同秒新暴露段、关门和新入侵。事后收到的请求不能倒填时间；同秒如何处理必须成为可重复的测试契约。
- 定时推进与普通操作调用同一套推进逻辑；一段超时只结算一次。
- 定时服务不能拿着锁等待 5 秒。写入 arrival_at 后立即释放，由后续 tick 到点处理。
- 推荐共享的短 tick 服务作为准时推进来源，HTTP 请求作为补偿；无人浏览时依然能处理到站、截止和收尾。
- 必须覆盖 valid、game 渲染、command、BOT／管理动作、房间退出和结算；不能只有 command 使用锁。
- 目前公共 process.lock 的范围与 RAID 请求锁关系要在实装时统一，禁止反向拿锁造成死锁；不要引入“新模式锁住整个网站等待动画结束”的实现。

仓库的 SQL 版本之间存在历史差异。本次确认的是**代码和建表声明**，不推断线上已经是什么结构。实装前需要生成实际部署结构清单、兼容迁移和回滚方案；不要在一次普通访问里无条件执行全库大规模 ALTER。

### 6.4 UI 与可见信息

至少新增／适配以下界面：

1. **电梯面板**：当前层、目标层、运行／停靠／入侵、到站倒计时、本人叫梯排位、自动登车状态、上／下按钮。

4. **交互面板**：对话、交换、谜语、签名、线索查看。提示需要的物品；不以猜命令名作为玩法。
5. **商店／保管箱／交易**：进度解锁、价格、个人限额、共享库存；交易用双方确认和冻结物品，避免地面丢物被第三人截取。
6. **个人笔记**：已读文本、密码线索、所指楼层、是否失效、收集进度。
7. **节点选择**：普通离开始终可识别；特殊结果条件；无尽的不可逆说明。
8. **个人结算及房间总结**：各自结果独立，仍参与者不会被某人的结局弹窗挡住。
9. **观战、地图、雷达、新闻、NPC 帮助、战报**：显示允许公开的楼层名称与状态，不泄露下一层全部蓝图。
10. **default 与 nouveau**：两套主界面、异步更新、移动端、快捷键均检查；不能只做一张旧模板截图。

乱码血条、闪烁 HUD、倒置场景可用于演出，但电梯按钮、剩余时间、伤害结果和退出操作必须保持可读。提供减少闪动选项。场景的假 SQL 文本用固定素材，不回显真实服务器报错。

### 7.6 商店、保管箱与交易建议

**商店：**

- 在停靠／运行的正常车厢开放，战斗入侵期间暂时关闭；服务端校验同样生效。
- 商品按玩家已实际参与的探索进度与房间最高已达节点共同解锁；只坐车路过不立刻买到终局装备。
- 基本恢复品设每人配额，稀有装备可使用共享库存。
- 回到已访问楼层不补货；到达新的进度节点按明确规则补货。
- 初始价格使用可获得货币预算计算，不能直接沿用取仓 220 等大房间价格。
- 暂停场外支援和跨局货币兑换，避免空降装备破坏本局成长。

**保管箱：**

- 本局个人容量建议 6 格，免费存取；不跨局保留实体装备。
- 普通线索在笔记中，不占箱；可交易关键物／献祭物仍是实体。
- 禁止从尸体接管他人的保管箱。
- 死亡或离场后，普通个人物品随结算清理；唯一公共关键物按配置退回节点／重新投送。
- 诅咒物存入箱不会自动抹去已生效的携带事件；采用“入箱拒绝”或“状态仍绑定本人”其中一种公开规则。建议前者。

**玩家交易：**

- 同车厢双方自愿、明确列出物品和数量、双方确认。
- 发起时冻结报价物，任一方下梯、进入入侵或离场即取消并归还。
- 提交前重新校验道具语义与实例 ID，避免换包后成交错误物品。
- 第一版可只做赠送，但要有指定接收人和接收确认，不将丢地当等价交易。

## 8. 可通过数值设计解决的问题

这里的“问题”严格指：**机制、资格与结算方式已经明确，调整数量、强度、概率、价格、时间等参数即可改善的失衡**。例如候梯无上限导致必死属于第 9 节挑战；有可靠候梯保护后，探索时间过短才属于数值问题。

### 8.1 当前机制给出的基准

YELLOWKNIFE 默认起始 HP／SP 为 400，movesp 为 15；移动和搜索都会进入体力成本计算。脚伤、冻结等会增加成本，体力不足还可能涉及生命代偿。原配置 coldtimeon=0，所以不能把“150 秒”直接当作固定数量的行动。[S06、S23]

一个仅用于预算的例子：

~~~text
假设每层：
移动 5 次 + 搜索 10 次 = 15 次基础行动
不计状态、姿态、技能修正，SP 约消耗 15 × 15 = 225
初始 SP 400，在没有回复时只够约 26 次基础行动

若最后两次移动是返程，至少预留 30 SP；
冻结／脚伤时还需按实际成本上调。

某补给 HS,50,∞：
每次回复50 SP且不扣次数，长期总回复没有上限；
提高普通SP药价格无法恢复该物品已经取消的稀缺性。
~~~

这不是实测 DPS 或通关率，只说明原案药品、动作频率和计时必须一起设计。

伤害也不能只看 att：新版包含攻防比、熟练度、武器系数、射程、命中、反击、属性、固定伤害，以及重枪等最大 HP 比例成分。敌人单纯加血不一定能按比例增加难度。[S14、S24]

## 9. 单纯数值设计无法解决的挑战

这里的“挑战”包括规则本身的矛盾和为这些规则必须新增的系统结构。降低触发率、加长时间、削弱伤害可以掩盖现象，却不能定义缺失的权利、身份、时序和结算。

| 编号 | 挑战与具体失效例 | 为什么调数值不够 | 必须作出的设计／系统调整 |
| --- | --- | --- | --- |
| C01 | 一人反复按方向，其他人一直等不到车 | 只要允许覆盖路线，就没有等候上界 | 固定已承诺行程、叫梯去重、排队优先级、自动登车与取消规则 |
| C02 | 楼外玩家按时返回，却被他人入侵锁梯耗死 | 死因与本人是否正确行动脱钩 | 候梯保护／确定救援；第 4.4 节选择候梯保护 |
| C03 | 同模板异楼层互相遇敌、拾物、踩雷 | 这是空间身份缺失，不是概率失衡 | 模板与实例分离、唯一 pls 或全链路复合定位 |
| C04 | 编号越界、无尽状态无限增长 | 不能用少刷几层冒充无限实例能力 | 扩容／有限槽位取舍、种子生成、仓储、回收与前沿限制 |
| C05 | 刷新才到站、下线免于超时、反复刷新多次入侵 | 按请求次数和真实时间是两套不同语义 | 服务端时钟与幂等 tick、动作前对账、事件截止 |
| C06 | 两人同时上梯／买最后一件／选择脱出导致复制或覆盖 | 概率再低仍可被并发稳定触发 | 同锁域、版本范围、原子消耗、操作去重与崩溃恢复 |
| C07 | 一人 end2 后所有人被踢出本局 | 使用了整局终结接口 | 独立个人结果、在场资格和统一房间收尾 |
| C08 | 一人继续无尽，使其他人永远错过出口 | 单梯无法同时服务互不相容的时间线 | 无尽全局提案与集合；或改变“一部电梯”的原设，本案采用前者 |
| C09 | 未响应、反对无尽的人被自动放逐 | 不同意不能等于放弃参与 | 提案失败可继续有限段；无响应不自动同意，不因提案被驱逐 |
| C10 | “安全区”里仍被毒、雷、远程道具或旧目标杀死 | 敌人概率设零只影响一条入口 | 明确伤害类别、统一目标授权、入侵白名单、旧动作失效 |
| C11 | 普通 DTS 默认 PVP 破坏合作与脱出目标 | 玩家关系尚未定义 | 默认全程禁止 PVP；若保留楼层 PVP，需要另列抢夺、追杀、尸体和奖励规则 |
| C12 | 多人入侵算不清谁被攻击、谁有贡献和战利品 | 当前是双方结算，不是现成团战房间 | 参与者快照、个人首次冲击、共享敌人、贡献和退出规则 |
| C13 | 投票留人变成小团体反复处决他人 | 执行者强度无关投票权和被害者处境 | 默认自愿；可选强制变体必须明示拒绝、平票、单人和救援协议 |
| C14 | 原样历史胜者技能缺失或一击秒杀且复制神器 | 历史数据不完整、来源规则不同 | 版本化白名单快照；标准化回响；旧数据兼容；奖励映射 |
| C15 | 镜像／无掉落敌人被偷窃、复活、灵俑绕过限制 | “不额外掉物”没有禁止其他资源出口 | 对实体定义可复制／可偷／可分解／可召唤许可及一次性标记 |
| C16 | 电梯安全刷搜索，理财／元素／熟练无限上涨 | 任何正收益在无限无风险行动下都会无界增长 | 安全动作不计探索成长，按有效楼层预算给成长；再调数值 |
| C17 | 猫粮／密码线索／关键材料根本没生成 | 稀有度不是可完成性保证 | 生成依赖检查、替代解法、公共关键物丢失恢复 |
| C18 | 阅读长文与 30 秒演出时被迫错过电梯或超时 | 理解速度和网络不同，事件无法靠“更简单的题”统一 | 笔记、个人阅读保护、可稍后阅读；全房间不为一人无限暂停 |
| C19 | 非战斗对象被 NPC 搜索、种火吸取和群体技能影响 | 属性强度不能表达“不是战斗目标” | 环境／对话实体与战斗实体区分；服务端授权 |
| C20 | 炮台方向、复制回合、半成品撤场没有现成语义 | 加 HP 不会生成来路、回合和退场状态 | 地图边与来源、事件计数、战斗阈值中止与正确收尾 |
| C21 | 回车厢再进同层，计时和物品全刷新 | 数值缩小只使刷得慢 | 同一实例库存消耗持久化、个人累计暴露、生成幂等 |
| C22 | 新人出生高危楼层／拿多套起装支援老玩家 | 公平出生与身份领取未定义 | 候乘保护、加入窗口、每账户每局一次、禁止重复激活 |
| C23 | 传送、DeathNote、全图召唤绕开楼层 | 能力目标域仍是整个 DTS 地图 | 各职业／道具兼容白名单和空间权限；必要时替代能力 |
| C24 | 一层改天气，别层玩家突然受到天气效果或复活 | 原天气是房间共享机制 | 场景演出与实际局部环境分离 |
| C25 | 所有文献占格，玩家不得不丢弃叙事内容才能活 | 文本收藏与战斗背包争用同一机制 | 普通文本进笔记，实体只保留有机械用途的证据／材料 |
| C26 | 无尽玩家滞留旧层，既不能回收又不断开新层 | 无限保留与有限内存不可兼得 | 活跃层上限、前沿集合、只回收无引用层，达到上限先接人 |
| C27 | 到站／脱出与超时死亡同秒，结果因请求先后不同 | 没有固定先后规则 | 同时间戳确定处理序列，操作接受时间和事件版本一致 |
| C28 | 结算把探索者当普通 PVP 胜者刷全局奖励 | 奖励归属和模式统计不同 | 模式成绩独立；全局奖励明确适配、封顶、去重；禁赌局误结 |
| C29 | 所有乘客断线或死光，入侵永远不结束 | 等待“有人点击”的事件不完整 | 硬截止、空车分支、故障恢复、自动解锁及接回楼外玩家 |
| C30 | 公开 NPC 简介、错误日志、历史回放暴露里设定或真实数据 | 这不是文字多少／概率问题 | 内部设定与公开台词分层；虚构错误素材；历史快照信息白名单 |

### 原案的 PVP／投票变体如何保留

如果作者认为背叛本身是梦中体验的核心，可以在主玩法成立后增加单独的房间选项：

- 楼层 PVP 开启、车厢 PVP 仍关闭。
- 强制留人投票只在已选择该变体的房间出现。
- 开局明确告知；不得中途临时切换。
- 对被留下者保留有成本但确实可用的返程／独立退出途径。
- 单独统计胜负，不与合作版成绩直接比较。

这是一项**设计分支**，不是把默认敌人发现率调高就能得到的模式。

## 11. 未来验收清单

本节是实装后应执行的验证，不表示本次已经做过这些测试。

### 11.1 核心规则和多人并发

- [ ] 1 人可完成普通节点脱出，不因最后存活自动提前获胜。
- [ ] 2 人在不同楼层相同模板地点，不能互相遇敌、协战、拾物、踩雷或共享机关库存。
- [ ] 同一层的人可按设计正常交易／协作；同房间实例唯一地点不会误隔开真正队友。
- [ ] 两人同时叫梯、按相反方向，调度顺序确定且已承诺接人不被覆盖。
- [ ] 连点按钮、网络重发、旧页面提交不会重复生成请求、刷新关门计时或多次收费。
- [ ] 开门截止与登车同秒、到站与入侵同秒、死亡与脱出同秒均符合固定优先序。
- [ ] 全车死亡、全车掉线、空车有楼外呼叫都能最终恢复调度。
- [ ] 入侵锁梯时，已候梯者不会因此被侵蚀杀死；自行离开保护立即恢复原预算。
- [ ] 同层多次上下梯不重置预算或刷新已消耗资源。
- [ ] 普通搜索不因另一楼层有人叫梯就全部被全局 revision 拒绝。
- [ ] 新人进入运行中／入侵中车厢不承担未参加事件的首次袭击。
- [ ] 自愿留守者在约定跨层行程完成前不能立即重新登车，单人不会卡在留守流程。
- [ ] 房间退出、个人脱出、死亡、重新登录都正确取消请求和交易，不重复起装。

### 11.2 安全、战斗和特殊对象

- [ ] 车厢自由攻击、focus／追击／协战、陷阱、毒物、远程与旧战斗入口服从同一权限。
- [ ] 普通伤害归零不会继续产生偷窃、经验、熟练、武器消耗等“假战斗”收益。
- [ ] 自然死亡、战斗死亡、复活、净化、死疗、休息均不能错误绕过或重复触发暴露。
- [ ] 每名入侵参与者的首次冲击恰好一次，迟加入者不被追补。
- [ ] 镜像不复制玩家身份／模式状态，不掉出第二套玩家装备；别人不能抢走私人事件收益。
- [ ] 错误 NPC 无额外掉落，也不可经尸体、偷窃、灵俑、分解取得隐藏收益。

- [ ] 大种火、远影、投影不能被种火索敌、全体伤害或召唤系统误当敌人。
- [ ] 从属 NPC 随主人上下梯正确更新空间；部署、召回、主人结算和旧层回收不丢失、复制或留下无主实体。
- [ ] 旧胜者没有技能参数、没有副武器或来源模式不同，仍生成合法回响；没有历史数据可用固定模板。
- [ ] 场景乱码不进入真实数值／SQL；计时、退出和事件代价始终可读。

### 11.3 资源、剧情和经济

- [ ] 多种随机种子下，每层存在通向电梯口的路径，事件必需资源存在可到达来源或替代解。
- [ ] 地图 ID 保留值、类型越界、缺模板、重复模板、未知物品参数都在生成时被检查。
- [ ] 129 行物品按用途加工，75 个 X 不会只有名字却无反馈。
- [ ] 每武器路线有最低可用装备、弹药／耐久、恢复与成长途径。
- [ ] 同层回访不重复刷物、尸体、公共奖励或稀有事件。
- [ ] 地面物、掉落、仓库、交易、奖励溢出时，背包满不会丢失关键物或复制物。
- [ ] 最后一份库存被同时购买，只成交一次；入侵开始后旧商店窗口不能继续购买。
- [ ] 诅咒转交／丢弃／存箱／死亡后，其事件归属符合公开说明。
- [ ] 谜语答错、无关键线索、长时间阅读不会关闭普通离开选项。

- [ ] 玩家帮助、NPC 图鉴、剧情和前端状态不包含内部解释／未探索完整蓝图。

### 11.4 结算、无尽与恢复

- [ ] 一人普通／特殊脱出，其他人仍能正常行动。
- [ ] 脱出者不算尸体、不再算仍参与者、不再被攻击；个人胜利故事可回看。
- [ ] 全员脱出、全灭、主动认输、限时封存、管理员中断分别保留正确个人结果。
- [ ] 结算重试不重复发账号奖励；默认不会触发普通 end2/end3、赌局或固定参赛收益的错误奖励。
- [ ] 无尽提案有反对／无回复会按规则取消，不把未同意者驱逐或强带入无尽。
- [ ] 全员同意后集合失败会取消发车；旧层有人时不越过不可返回边界。
- [ ] 达到活跃实例预算时停止向前生成、优先接人，不回收有人／有事件引用的层。
- [ ] 在生成、扣费、登车、伤害、奖励、关房中途模拟进程退出，恢复后不重复、不遗失。

## 12. 已提出的默认决策与仍待作者定稿的内容

### 12.1 本文采用的默认建议

这些建议使文档能够用于下一轮设计评审；它们不是已经获得作者确认的实装指令。

1. 保留单部共享电梯，使用不可随意覆盖的请求队列。
2. 默认合作 PVE；强制 PVP／投票留人为后续独立变体。
3. 采用真实时间，候梯保护，按个人每层累计暴露。
4. 新生在车厢候乘，有限加入窗口，无尽不开放新激活。
5. 初始有限段为 0 与 ±1…±7；2—5 内容点另加电梯口。
6. 普通脱出不依赖谜语，特殊结局靠可获得的本局线索。
7. 个人结果单独存储，房间封存是另一层收尾。
8. 无尽必须集体同意并集合；保留主动认输以结束个人挑战。
9. 模板与运行实例分离，推荐扩容实际地点字段；无尽仍实行有界实例管理。
10. 文献进入笔记，关键物才占实体格；本局个人仓库，不继承夺箱机制。
11. 历史胜者用标准化回响；镜像与错误 NPC 不提供复制装备通道。
12. 不默认接入普通胜率、赌局、场外支援与跨局奖励。

### 12.2 仍需要内容创作／作者判断的部分

- **里设定正典：**帧间夹层的性质、钻探挖出之物、相关人物因果。本文没有替作者补造“真相”，仅规定玩家如何接触线索。
- **大种火谜语：**种火语字典、可验证解码规则、具体题库、提示层级和特殊条件。不能只写“输入正确密码”而没有实际可解信息。
- **阁楼素材：**可移植的既有结局、可使用的玩家梗角色、回放片段。需要作者选材及公开文本整理。
- **每件 X 的用途：**哪些只收藏、哪些交易、哪些支撑终点。129 行原物品须逐条定稿用途与参数，本文提供完整加工分类。
- **电梯封存是否还有剧情目标：**本文将其定义为房间收尾；若希望是隐藏通关路线，应另补触发物、前置条件、群体同意、成功／失败和奖励，不直接沿用空白 end8。
- **梦中体验的恶意程度：**若“别人把你甩在楼里”“必须投票牺牲一人”是不可放弃的核心，需要另选第 9 节变体，并接受其与合作版不同的体验目标。
- **无尽的主要评价：**最高有效深度、总贡献还是收藏完成度，建议主榜采用有效深度，贡献作为同层排序参考，避免单纯坐车刷记录。
- **职业范围：**完整逐社团实测之后决定禁用／替代清单；不能在没有验证的情况下宣称沿用全部技能即可平衡。
- **最终数值与素材规模：**第 8 节只是首轮测试输入。有限段层数、时间、人数、资源密度和入侵强度都需基于实测定稿。

## 结语

这个模式最有价值的部分是“随机门后的探索”和“共享电梯带来的相遇与分离”。目前源代码已经能承担角色、装备、普通战斗和大量表现，但尚未提供共享载具、独立楼层实例、个人脱出及可靠真实时间事件的完整组合。

下一步应先定下调度、候梯、个人结果、无尽承诺四条协议，再完成数据与实例基础，最后把原案的八池素材加工成真正有输入、反馈和结束条件的玩法。这样可以保留梦里光怪陆离的感觉，同时让失败来自可以理解的风险选择，让系统行为在多人场也能被解释和验证。
